# 标题、形式与术语

这份文件管三件事：标题怎么起、内容用什么形式承载、名词怎么用。它们共同决定文章「看起来是不是一篇有人编排过的技术文章」，而不是模型一口气吐出来的长文。

## 一、标题系统

模型写长文最常见的失控点：标题起得随意，小标题一层套一层，读者读完记不住脉络。

解决方式是**分层标题**：H2 负责定位，H3 负责给信息，H4 只在同一 H3 下确实有多个并列细分时补一层。

### 1. 分层分工

| 层级 | 作用 | 句式 | 例子 |
|---|---|---|---|
| H1 | 文章讲什么 | 名词短语 | FlashAttention：分块与在线 Softmax |
| H2 | 读者现在读到哪一块 | 惯常板块名，可以笼统 | 研究背景、方法原理 |
| H3 | 这一块建立了什么判断；若其下还有 H4，可只做分组 | 陈述式、具体；分组时可短 | 分块让 Softmax 不必看到完整一行 |
| H4 | H3 下的并列细分判断 | 陈述式、具体，比 H3 更窄 | 封存参考隔离、里程碑契约与运行内修订 |
| H5 及更深 | 不用 | — | — |

H2 是给读者定位的，不需要有信息量；H3 才承担论证。两者缺一不可：只有 H2，读者知道在读「方法」，却不知道方法主张什么；只有具体标题，读者读几节就失去方位。H4 不承担主干论证，只在同一 H3 下确实存在多个并列判断时使用；能合并成一段正文就不设。

### 2. H2：定位层

常见候选，可以按需选、合并、改名：

| 候选 | 什么时候用 |
|---|---|
| 主要工作 | 开头先给结论 |
| 研究背景 | 读者缺前置 |
| 问题定义 | 约束本身需要单独讲 |
| 方法原理 | 有机制要解释 |
| 实验与证据 | 有数据要核对 |
| 局限性 | 有边界要交代 |
| 结论 | 收束全文 |
| 相关工作 | 核心贡献只有在对比中才看得清 |

规则：

- 数量 4–7 个（含可选的答疑）。
- 用名词短语，允许笼统。
- **顺序不固定。** 按读者理解的依赖排，不按论文的章节顺序，也不按上面表格的顺序。读者已经懂背景，就先把方法放前面；局限可以并进实验；相关工作可以整节删掉。
- 不要为了凑齐候选而写空章节。表格是菜单，不是目录。

### 3. H3：论证层

规则：

- 陈述式，不用问句。
- 具体到能说出判断，不能只是「分块」「实验设置」「结果分析」。
- 每个 H2 下 0–4 个。只有一个且不并列时，不设 H3，直接写正文。
- 全篇 H3 不超过 12 个。
- 标题必须能被正文兑现：标题说「图 2 支持 IO 是主要成本」，正文就得给出支持它的数字。
- 如果这个 H3 下面还有 H4，H3 可以只做分组标题（如「核心机制」）；没有 H4 时，H3 必须写成判断句。

| 不推荐（H3） | 推荐（H3） |
|---|---|
| 为什么需要分块？ | 分块让 Softmax 不必看到完整一行 |
| 实验结果分析 | 图 2 支持 IO 是主要成本 |
| 方法介绍 | 反向传播不保存概率矩阵，需要时重算 |

**H4 的使用边界**：

- 只在同一个 H3 下有两个以上并列、且各自需要独立段落的判断时使用；单个 H3 下的 H4 不超过 4 个。
- H4 仍要写陈述句，不能退化成「封存参考」「知识库」这类话题标签。
- 不要把 H4 当作逃避拆分 H3 的手段：如果 H4 之间没有并列关系，应该合并回正文或提升为 H3。
- 不用 H5 及更深；再细的内容用列表、表格或 `::: details` 承载。

### 4. 预算

以 6000–9000 字为目标：

| 层级 | 数量 |
|---|---:|
| H1 | 1 |
| H2 | 4–7 |
| H3 | ≤ 12 |
| H4 | 按需，单个 H3 下 ≤ 4 |
| H5 及更深 | 0 |

全篇 H2–H4 标题总数控制在 24 个以内。超过这个数，先检查是不是把段落当成了章节。

### 5. 连读测试

分两次读：

- **只读 H2**：应该像一张地图，能看出文章分几块、大概什么顺序。这里读出「话题清单」是正常的。
- **H2、H3 和必要的 H4 一起读**：应该像一条论证链，能看出每块建立了什么判断。这里读出「话题清单」才是失败。

正常的样子：

```text
## 研究背景
### 标准实现把 N×N 中间结果搬了四次
### 分块之后，片上只保留一个块
## 方法原理
### 在线 Softmax 让分母可以增量维护
### 反向不保存概率矩阵，需要时重算
## 实验与证据
### 图 2 支持 IO 是主要成本
## 局限性
```

失败的样子：

```text
## 研究背景
### 背景介绍
## 方法原理
### 分块
### 在线 Softmax
### 重算
### IO 复杂度
## 实验
### 实验设置
### 实验结果
```

问题不在 H2——H2 本来就该笼统。问题在 H3：它们是话题标签，没有判断，读者读完不知道作者主张什么。

### 6. 细则

- 同级标题保持同一形式。H2 都是名词短语，H3 都是陈述句，不要混。
- 标题里不重复文章标题已有的词。
- H3 不用「概述」「浅谈」「初探」「其他」「补充」「小结」这类空标题。
- 唯一允许问句的地方是**阅读答疑**的小节标题。
- H2 超过 24 个字，多半是把 H3 的内容写到了 H2 上，降一级。

### 7. 自检

对每个 H3 问：**这节建立什么判断？** 答不出来，或者答出来是「介绍 X」，就删掉标题，把内容并进相邻段落。

对每个 H2 问：**读者靠它能不能定位？** 定位不了，说明板块名太抽象或分得太碎。

## 二、形式选择

不同内容用不同形式承载。模型倾向于把所有东西写成段落、并且把所有推导平铺在正文主干里，这正是「读起来平、读到方法章节就被劝退」的根源。

| 内容 | 用什么 | 不要用 |
|---|---|---|
| 一句补充、前提、易错提醒 | `::: tip` / `::: warning` 容器，或脚注 `[^1]` | 硬塞进正文段落 |
| 多步公式推导、所有正式算法伪代码（算法 0/1/2）与符号表、手算算例全套、次要背景注记与指标公式 | `::: details 点击展开：<具体内容>` 折叠容器 | 平铺在主干正文阻塞轻度读者，或把算法 0 放主干、算法 1 放折叠框 |
| 引用论文原话 | `>` 引用块，附页码 | 改写后不加引号 |
| 两个以上对象、同一组维度对比 | 表格 | 连续段落罗列 |
| 算法伪代码 | `>` 引用块 + 有序列表 + `&emsp;` 缩进 + `$...$` 渲染数学公式（放入 `::: details`） | ` ```text ` 纯文本代码块（导致 `R^(N×d)`、`B_c`、`m_i^new` 等符号未渲染） |
| 流程、依赖、数据流 | 论文原图，或自绘 SVG | Mermaid（站点未装插件，见下） |
| 核心结论公式 | `$$...$$`，主干按 `(1), (2), ...` 连续编号（每小节最多 1 个） | 纯文字描述公式 |
| 两步以上的公式推导或数值代入 | `aligned` 多行公式（一步一换行 + 右侧注记依据）或有序列表 | 在自然段里用分号串联公式、单行长连等式 |
| 变量、符号、命令、路径 | 行内数学或行内代码 | 普通正文 |
| 关键判断与核心视觉焦点 | 粗体断言句（单独成段）+ 单一暖底 `<mark>` 高亮 | 红绿金多色文字混排、大面积加粗、整段涂色 |

### 1. 补充说明与分层折叠：容器或脚注

短的旁注用脚注，读者可以跳过：

```markdown
这里的 $M$ 以标量元素个数计[^m-unit]，不是字节数。

[^m-unit]: 论文 §3.1 的符号表用元素个数定义 M；换算成字节还要乘数据类型宽度。
```

独立成段的单条提醒用提示容器（一段以内）：

```markdown
::: warning
论文的基准只在 A100 上做，换到其他架构需要重新测量。
:::
```

**伪代码、手算算例、重度推导必须统一用 `::: details` 折叠容器（渐进披露 + 主干独立成文）**：

为了同时满足「5 分钟通读核心脉络」的轻度读者与「逐行核对伪代码、公式推导和手算算例」的深度读者，文章采用**主干极简成文 + 折叠框深读**双层设计：

- **主干层（默认可见，必须独立成文）**：
  - 只放断言句、核心机制与 2–3 条动作步骤、每小节最多 1 个核心结论公式（或核心原图/实验汇总表）、具体后果，配合克制的 `<mark>` 暖底高亮突出最关键结论与数字。
  - **不展开任何 `::: details` 时，外部主干必须是一篇逻辑通顺、因果闭环、过渡自然的完整文章**：前节末尾提出的硬约束必须被后节主干直接接住解答，主干中出现的每个变量与公式编号 `(1), (2), ...` 必须在主干内自洽定义，严禁引用折叠框内部才定义的符号或式号。
- **折叠层（默认收起，点击下拉展开）**：统一收纳以下五类内容：
  1. **所有正式算法伪代码与符号对照表**（包括基线算法 0、前向算法 1、反向算法 2，排版标准必须全文统一，不得有的放主干、有的放折叠框）；
  2. **手算算例全套内容**（含算例输入设定、SVG 状态流转图、各轮状态汇总表、四步逐轮手算代入过程，整体作为一个 `::: details` 附在对应机制小节末尾，不在主干单开算例小节）；
  3. **多步数学推导**（如在线 Softmax 分母与分子的换基推导、反向传播求导链与 $D_r$ 化简、SRAM 分块大小与 IO 访问次数定量核算）；
  4. **次要背景注记与扩展对比**（如稀疏/低秩近似的具体分类、点积缩放机制补充、与后续版本 FlashAttention-2 的循环顺序对比）；
  5. **评估指标的数学定义展开**（如困惑度 PPL 的负对数似然公式与采样温度对比）。

```markdown
::: details 点击展开：在线 Softmax 跨块换基与部分输出更新的分步推导
1. **防止指数上溢（平移不变性）**：对单块向量 $x\in\mathbb{R}^B$，取块内最大值 $m(x) := \max_a x_a$，分子分母同乘 $e^{-m(x)}$：
   ...
:::
```

折叠容器规则：

- **标题必须写清展开后有什么**，统一用 `::: details 点击展开：<具体内容>`，禁止只写 `::: details 详细推导` 或 `::: details 更多细节`。
- **禁止三冒号容器嵌套**：在 `::: details` 内部不要再写 `::: warning` 或 `::: tip`（Markdown 解析器遇到内层 `:::` 会提前闭合外层折叠框）；折叠框内部的提醒改用引用块 `> **注意**：...`。
- **折叠框内同样受证据账本约束**：折叠框不是免检区，里面的公式、数据、锚点与推导步骤必须与论文严格一致。

### 2. 对比：表格

对比表要求：

- 列是维度，行是对象；或者反过来，但全文统一。
- 每个对象用同一组维度、同一顺序。
- 表头写清单位和条件。
- 数字右对齐，文字左对齐。
- 表后必须有一句话说明「这张表改变了什么判断」，不能只放表。

### 3. 多步过程：伪代码（必须经 MathJax 渲染数学符号，统一收进 `::: details`）

**严禁使用 ` ```text ` 纯文本代码块编写算法伪代码！** 在 ` ```text ` 代码块中，Markdown 不会调用 MathJax 渲染公式，导致读者看到 `R^(N×d)`、`B_c = ⌈M / (4d)⌉`、`m̃_ij`、`m_i^new` 这类粗糙的纯文本符号，极难阅读。

所有正式算法伪代码必须统一收进 `::: details 点击展开：算法 N（...）`，并采用 **引用块卡片（`>`）+ 有序列表 + `&emsp;` 缩进 + `$...$` LaTeX 数学公式** 编写，使每一个数学符号都被 MathJax 渲染为标准公式：

```markdown
> **算法 1：FlashAttention 前向计算**（来源：[论文，§3.1 算法 1](https://arxiv.org/pdf/2205.14135v2#page=5)）
> - **输入**：HBM 中的矩阵 $Q, K, V \in \mathbb{R}^{N\times d}$，容量为 $M$ 的片上 SRAM
> - **输出**：HBM 中的精确注意力矩阵 $O \in \mathbb{R}^{N\times d}$
>
> 1. 设置块大小：$B_c = \lceil M / (4d) \rceil$，$B_r = \min(\lceil M / (4d) \rceil, d)$
> 2. 在 HBM 中初始化：$O = (0)_{N\times d} \in \mathbb{R}^{N\times d}$，$\ell = (0)_N \in \mathbb{R}^N$，$m = (-\infty)_N \in \mathbb{R}^N$
> 3. **for** $1 \le j \le T_c$ **do**（外循环：遍历键/值块）
> 4. &emsp;从 HBM 加载 $K_j, V_j$ 到片上 SRAM
> 5. &emsp;**for** $1 \le i \le T_r$ **do**（内循环：遍历查询块）
> 6. &emsp;&emsp;在片上计算分数块：$S_{ij} = Q_i K_j^{\mathsf T} \in \mathbb{R}^{B_r \times B_c}$
> 7. &emsp;**end for**
> 8. **end for**
> 9. **return** $O$
```

规则：

- **全文所有算法统一放进 `::: details`**：不得把算法 0 放在主干、把算法 1 放在折叠框。
- **所有数学符号必须写在 `$...$` 内**：矩阵维度写 `$\mathbb{R}^{N\times d}$`，上下标写 `$Q_i, K_j^{\mathsf T}, m_i^{\mathrm{new}}$`，波浪号写 `$\tilde{m}_{ij}, \tilde{P}_{ij}, \tilde{\ell}_{ij}$`。
- **控制流关键字加粗，循环体用 `&emsp;` 缩进**：`**for** ... **do**`、`**end for**`、`**return**` 加粗；一层循环缩进一个 `&emsp;`，二层循环缩进 `&emsp;&emsp;`。
- **每行只做一件事**：避免把两三个长公式赋值塞在同一行，必要时拆成连续编号的多行。
- 伪代码之后紧跟符号对照表或关键行说明。

### 5. 公式与步骤推导：一步一换行

模型写公式推导最常见的两类排版灾难：一是把三四步推导用分号挤进同一个自然段（「由 A 可知 B；由 B 可知 C；最后由 C 得到 D」）；二是把多个等号横向连成一长行（`A = B = C = D`）。这两种写法都会让读者在符号堆里迷路。

硬性规则：

1. **禁止在自然段内连续推导**：凡涉及两步及以上的因果链、求导链、变量代换或数值代入，**必须拆成有序列表或分步块，一个步骤一换行**，绝不用分号在段落内串写。
2. **列表项单行单动作**：哪怕已经写成有序或无序列表，单个列表项内也只写**一个计算动作**；禁止把「刷新最大值；算旧块系数 $\alpha$；算新块系数 $\beta$」用分号挤在同一个列表项里，必须拆成缩进子列表逐行写。
3. **多步等式必须「一等号一换行 + 标明变换依据」**：两个以上有实质代数变换的等号，必须放进 `$$\begin{aligned} ... \end{aligned}$$`，每个等号用 `\\` 单独占一行，并在行末用 `&&\text{（本步变换依据）}` 对齐注明做了什么操作。
4. **精确代数化简（`=`）与数值代入近似（`\approx`）分行写**：禁止把展开式和最终约等数值挤在同一行（例如 `= e^{-2} + e^{-1} + 1 + e^{-3} \approx 1.5530` 必须拆为两行：第一行写精确表达式，第二行 `&\approx 1.5530` 给数值结果并标依据）。
5. **文字步骤与公式交替时，先写步骤动作，再换行给公式**：每一步用 `1. **本步动作**：一句说明` 开头，独立公式或分项子列表另起一行，不把多条长公式塞在文字句中。

**反例（连续段落推导 + 单行长连等式，严禁出现）**：

> 由 $O = PV$ 可知 $dV = P^{\mathsf T} dO$ 且概率梯度为 $dP = dO V^{\mathsf T}$；由 $P = \operatorname{softmax}(S)$ 可知分数梯度满足 $dS_{rt} = p_{rt}(dP_{rt} - \sum_u p_{ru} dP_{ru})$；最后由 $S = QK^{\mathsf T}$ 得到 $dQ = dS\,K$ 与 $dK = dS^{\mathsf T} Q$。其中行内求和项为：
> $$D_r = \sum_{u=1}^{N} p_{ru} (dP_{ru}) = \sum_{u=1}^{N} p_{ru} (dO_r v_u^{\mathsf T}) = dO_r \cdot \left(\sum_{u=1}^{N} p_{ru} v_u\right)^{\mathsf T} = dO_r \cdot o_r^{\mathsf T} = \operatorname{rowsum}(dO_r \odot o_r)$$

**正例（一步一换行 + 每步标明依据）**：

> 已知损失对输出 $O$ 的梯度 $dO\in\mathbb{R}^{N\times d}$，反向传播按链式法则分三步求取输入梯度：
>
> 1. **由 $O = PV$ 求值梯度与概率梯度**：
>    $$dV = P^{\mathsf T} dO, \qquad dP = dO\,V^{\mathsf T}$$
> 2. **由 $P = \operatorname{softmax}(S)$ 求分数梯度**（第 $r$ 行、第 $t$ 列）：
>    $$dS_{rt} = p_{rt}\!\left(dP_{rt} - D_r\right), \qquad \text{其中 } D_r := \sum_{u=1}^{N} p_{ru}\, dP_{ru}$$
> 3. **由 $S = QK^{\mathsf T}$ 求查询梯度与键梯度**：
>    $$dQ = dS\,K, \qquad dK = dS^{\mathsf T} Q$$
>
> 其中第 2 步的行内求和项 $D_r$ 按如下步骤化简为前向输出 $O$ 与 $dO$ 的逐元素点积：
>
> $$
> \begin{aligned}
> D_r &= \sum_{u=1}^{N} p_{ru}\, dP_{ru} &&\text{（Softmax 反向行内加权和定义）} \\
> &= \sum_{u=1}^{N} p_{ru} \left(dO_r v_u^{\mathsf T}\right) &&\text{（代入第 1 步 } dP_{ru} = dO_r v_u^{\mathsf T}\text{）} \\
> &= dO_r \cdot \left(\sum_{u=1}^{N} p_{ru} v_u\right)^{\mathsf T} &&\text{（提出与求和下标 } u \text{ 无关的 } dO_r\text{）} \\
> &= dO_r \cdot o_r^{\mathsf T} &&\text{（括号内即前向输出定义 } o_r = \sum_u p_{ru} v_u\text{）} \\
> &= \operatorname{rowsum}(dO_r \odot o_r) &&\text{（写成行向量的逐元素乘积求和）}
> \end{aligned}
> $$

### 6. 不同内容用不同排版层级与克制视觉引导

为了让读者在快速扫读主干时一眼抓住核心判断，同时避免中英公式混排下「五颜六色 + 到处加粗」带来的视觉杂乱，全文采用**单一暖底高亮 + 克制加粗**纪律：

| 内容类型 | 排版 / 样式写法 | 适用场景与纪律 |
|---|---|---|
| 正文 | 默认 | 英文、中文与行内公式自然衔接 |
| 术语首次出现 | 中文（English, ABBR）或 **核心中文词** | 只对真正关键的核心概念加粗，不要把整段里的 5–7 个术语全加粗 |
| 变量、公式 | `$...$` / `$$...$$` | 尽量避免在 `**粗体**` 或 `<mark>` 中直接包入复杂公式（SVG 笔画不随字重加粗，易显断层） |
| 命令、路径、标识符 | `` `...` `` | 不用全角引号 |
| 章节断言句 | **粗体短句，单独成段** | 每个 H2/H3 开头第一句 |
| **核心结论 / 关键收益高亮** | `<mark>核心结论或对比数字</mark>` | 使用站点统一暖金底色（`--cf-warm`），每小节最多 1–2 处 |
| 补充说明 | `::: tip` / `::: warning` 或脚注 | 不超过一段 |
| 深度推导 / 伪代码 / 算例 | `::: details 点击展开：<具体内容>` | 默认折叠，不阻塞主干 |

视觉引导纪律：**严禁在正文中使用多种高饱和彩色字体（如红/绿/金混排）**；`aligned` 多行公式右侧的 `\text{（依据）}` 控制在 12 字以内，确保在 `::: details` 内不横向截断。禁止使用斜体表示强调（中文斜体难读）、下划线（会被当成链接）。

## 三、用词

### 1. 少用比喻

比喻不能承载论证。规则：

- 默认用机制解释，不用比喻代替。
- 全文最多一个总类比，且必须先给准确解释，再说明类比的适用边界。
- 禁用这些说法：流水线、大脑、积木、把数据喂给、串起来、魔法、黑盒（除非论文自己这么叫）。
- 检验方法：删掉比喻，论证还成立吗？不成立，说明论证本身没写出来。

### 2. 不自造术语

术语来源优先级：

1. 论文原文的用词。
2. 标准教材或官方文档的译名。
3. 社区通用译名。

需要简写时，首次出现写全称并声明：

> 高带宽显存（High Bandwidth Memory, HBM，以下简称 HBM）

不要做这些事：

- 把动词硬名词化：「分块化」「重算化」「并行化处理」。
- 给同一个对象起两个名字，后文换着用。
- 用「我们称它为 X」发明一个只在本篇有意义的词。

同一个对象全文只用一个名字。换名字会让读者以为是两个东西。

### 3. 首次出现必须解释

以下三类词，第一次出现就要解释，不能拖到文末术语表：

- 论文自己定义的术语（如 IO-aware、exact attention）
- 冷门概念或领域缩写
- 你在正文里要反复使用的简称

解释放在**读者第一次需要它**的位置，格式是「是什么 + 为什么这里需要它」，一句话到两句话。不解释读者已经知道的（Python、矩阵乘法、softmax 的基本定义）。

### 4. 重要名词附英文与缩写

首次出现：

> 高带宽显存（High Bandwidth Memory, HBM）
> 片上静态随机存取存储器（Static Random-Access Memory, SRAM）

之后固定用中文或缩写，不要混着换。论文标题首次出现给英文原名，必要时附中文译名。

### 5. 重要名词附链接

- 只链一手来源：官方文档、论文原文、标准、项目仓库。
- 不链二手博客、课程笔记、内容农场。
- 每个术语只在首次出现时链一次，后文不重复链。
- 站内已有页面用相对路径链站内，不要外链到别处。
- 链接文字要有信息量，写「CUDA 编程指南」，不写「点击这里」。
- 优先稳定 URL。arXiv 用 `abs` 页，官方文档不要链带版本号的临时页。
- 一篇报告 3–8 个外链足够。每个名词都链会让正文变成链接列表。
