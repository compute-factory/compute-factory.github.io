# 材料、证据与断言

这份文件解决两个问题：**怎么让报告不编**，以及**怎么让报告敢下结论**。前者靠账本，后者靠断言阶梯。两件事都做，才不会写出「满篇可能、读完什么也没说」的文章。

## 一、材料处理

### 1. 论文

先确认版本。arXiv 的 v1 和 v2 可能改过实验、补过附录，页码也会变。把版本写进导语，后面所有锚点以这个版本为准。

```bash
pdftotext -layout paper.pdf paper.txt
```

- `-layout` 保留分栏和表格的列位置，比默认模式更适合对数字。
- 图片不要用文本凑。用 Read 直接打开 PDF 的对应页看，或让用户提供截图。**拿不到真图就不要放图**，用文字描述并说明原图在论文哪一页。
- 公式在 `paper.txt` 里通常会散架。公式以 PDF 页面或论文 HTML 为准，不要照着文本文件里的乱码重写。

### 2. 论文结构图

读完全文后，先列一张表，不要急着写：

| 部分 | 页码 | 它在论证里干什么 |
|---|---|---|
| Abstract | 1 | 作者自己声称的贡献 |
| §2 背景 | 3–4 | 建立成本模型 |
| 算法 1 | 5 | 前向流程 |
| 图 2 | 6 | IO 与耗时对比 |
| 表 1–2 | 7–8 | 端到端训练结果 |

这张表决定后面两件事：哪些图和表值得进正文，哪些章节只需要一句话带过。

### 3. 聊天记录

聊天记录的用途是**读者卡点报告**：它告诉你读者在哪里停住了、带着什么错误前提。它不是选题清单，也不是证据。报告写什么由论文的论证结构决定，问题只能调整某处讲多讲少。

把问答对切开，只保留**问题**和读者自己的话。模型的回答降级为线索：它告诉你「这里可能有个坑」，不告诉你「坑是什么」。

处理时标出三类：

- **读者反复问的** —— 那个位置大概率缺定义或跳了步，回正文补。
- **模型答得很自信但论文没写的** —— 幻觉高风险区，回论文核实，核实不了就丢。
- **读者自己纠正模型的** —— 说明读者在某个点上比模型读得深，可以用来校准那一段该讲多细；但不要因为读者关心，就把它升级成一条主线。

### 4. 笔记

笔记里的疑问、划线、公式推导都保留原样。不要先把笔记「整理成提纲」再写，那会把读者真实的思路磨平。

## 二、证据账本

在临时目录建 `evidence.md`。正文里的每个事实、数字、图表结论，都要能指回某一行。

```markdown
| ID | 位置 | 原文或数据（照抄） | 支撑什么结论 | 强度 |
|---|---|---|---|---|
| E1 | §3.2 / 图 2 / p.6 | HBM 读写 40.3 GB → 4.4 GB | IO 是主要成本 | L2 |
| E2 | 表 1 / p.7 | BERT-large 20.0 ± 1.5 → 17.4 ± 1.4 分钟 | 端到端训练加速 | L2 |
| E3 | §3.1 / 算法 1 第 11 行 | `m_new = max(m, m_tilde)` | 在线 Softmax 的换基 | L1 |
```

**位置格式统一**：`§章节 / 图或表或算法 / p.页码 / 行号`。后面写正文时，这个位置直接变成锚点：

```markdown
[论文，§3.2、图 2](https://arxiv.org/pdf/2205.14135v2#page=6)
```

### 什么算证据

| 算 | 不算 |
|---|---|
| 论文正文的陈述，带章节位置 | 模型的解释 |
| 表格和图中的具体数值 | 二手博客、课程笔记 |
| 算法伪代码的某一行 | 你对作者意图的猜测 |
| 附录里的推导 | 「一般来说」「众所周知」 |
| 作者明确写出的局限 | 其他论文的结论 |

外部背景（HBM 是什么、A100 的规格、Softmax 的定义）可以写，但要和论文主张分开：要么是读者已知的公共知识，要么标「补充背景」并给来源。**外部资料不能用来支持「这篇论文证明了 X」。**

## 三、断言阶梯

防御型回答的根因通常不是模型谨慎，而是它没有定位到证据，只好用语气兜底。解决办法是先把每句话归到某一级，再决定用什么语气。

| 级别 | 含义 | 怎么写 | 要不要限定 |
|---|---|---|---|
| **L1 原文陈述** | 论文明确写出 | 直接陈述，句末给锚点 | 不需要 |
| **L2 实验支持** | 图表直接给出的数据，且只在实验条件下成立 | 陈述 + 条件 + 锚点 | 条件本身就是限定 |
| **L3 机制推断** | 由论文机制可以推出，但论文没直接说 | 写出推导步骤，用「由此可得」连接 | 需要，限定语必须指向推导链 |
| **L4 论文未覆盖** | 论文没做、没测、没报告 | 「论文没有报告 X」 | 这是事实陈述，不要软化成「可能」 |

### 语气规则

1. L1、L2 用陈述句。不要加「我认为」「可以认为」「或许」。
2. L3 必须把推导写出来。读者能沿着推导判断你的推断是否成立，就不需要你替他犹豫。
3. L4 直接写缺口。**「论文没测 H100」比「可能在不同硬件上效果不同」信息量大得多。**
4. 作者自己的 hedging 保留为作者的主张（「作者认为」「论文将此列为局限」），不要升级成事实，也不要转写成你的犹豫。
5. 不确定性必须是**可命名的**：指向具体条件、数据集、硬件、版本。命名不了的不确定性，通常说明你还没查。

### 防御型改写对照

| 防御型写法 | 问题 | 改写 |
|---|---|---|
| FlashAttention 可能通过减少 IO 提升了训练速度。 | 论文报告了明确结果，却用「可能」 | FlashAttention 把 GPT-2 medium 的训练时间从 21.0 天降到 6.9 天（8×A100，对照 Hugging Face 实现）。同一张表里它的 FLOPs 还高 13%，下降来自 HBM 读写。 |
| 不能认为该方法在所有硬件上都有效。 | 空泛免责，没有信息 | 论文的基准只在 A100 上做；H100、消费级 GPU 和推理负载都没有测。 |
| 这或许说明 IO 是瓶颈。 | 证据就在手边，却没写出来 | HBM 读写从 40.3 GB 降到 4.4 GB，耗时从 41.7 ms 降到 7.3 ms，计算量反而增加 13%。耗时跟着读写量走，没有跟着计算量走。 |
| 作者可能希望解决长序列问题。 | 猜意图 | 论文的动机是长序列：标准实现的中间矩阵随 N² 增长，40 GB A100 在长上下文下放不下。 |
| 该方法具有一定局限性。 | 结论句没有内容 | 稠密版本仍然计算全部查询–键配对，时间主项随序列长度平方增长。 |

### 禁用与慎用

**直接禁用**（除非是引用原文）：可能、或许、也许、似乎、大概、不能确定、难以断言、有待进一步研究、尚无定论。

**慎用**：显著、大幅、极大、非常、至关重要。这些词的位置应该让给数字。

**不是禁用，但要想清楚**：「一般来说」「通常」。用之前问自己：有没有反例？有就写条件，没有就删掉。

## 四、论文幻觉陷阱

按出现频率排序，逐条检查：

1. **摘要数字和表格数字不一致。** 摘要常取整或取最好结果，正文以表格为准，并说明口径。
2. **版本混淆。** v1 的实验可能被 v2 改过。锚点、页码、结论全部锁定同一版本。
3. **模型规模张冠李戴。** GPT-2 small / medium / large、7B / 13B / 70B，写之前回表格对一遍。
4. **把相关工作算成本文结论。** 「Transformer 的复杂度是 O(N²)」是背景，不是这篇论文的发现。
5. **单位混淆。** GB 与 GiB、ms 与 s、token/s 与 samples/s、单卡与整机。
6. **图号表号编造。** 每引用一张图，确认它在 PDF 里真的存在且编号一致。
7. **把动机写成结论。** 「论文以此为前提」和「论文证明了」是两件事。
8. **丢掉实验条件。** 没有硬件、批量、序列长度、对照基线的数字，等于没有数字。
9. **附录与正文混用。** 附录的推导可以引用，但要标明位置；反过来，不要把正文的简化说成严格证明。
10. **百分比方向搞反。** 「降低 13%」和「降低到 13%」差一个数量级。
11. **把解释性算例写成实验。** 自己构造的小例子必须标「本文构造」，不能写成论文跑过。
12. **把作者的主张写成客观事实。** 保留「论文声称」这层归属。

## 五、数字搬运规则

- 原样抄。不改有效数字，不四舍五入，不补单位换算。
- 带条件。至少包含硬件、规模、对照基线中的相关项。
- 保留误差和区间。`20.0 ± 1.5` 不要写成 `20`。
- 自己算出来的数字要标出来，并给出算式。例如 `4.45 倍` 后面跟一行计算过程，不要让读者以为是论文数据。
- 同一个指标全文只用一个口径。前文用分钟，后文不要突然换成小时。
- 数字很多时用表。表格的每一列含义写清楚，不要只放两列裸数字。

## 六、核验清单

写完逐项过：

- [ ] 每个结论句都能在 `evidence.md` 找到条目
- [ ] 每个数字都有单位、条件、锚点
- [ ] 每个 `#page=N` 锚点都抽查过
- [ ] 没有把 L3 推断写成 L1 事实
- [ ] 没有把 L4 缺口写成模糊的「可能」
- [ ] 论文版本在全文一致
- [ ] 自己构造的算例都有标注
- [ ] 外部背景知识和论文主张分开
