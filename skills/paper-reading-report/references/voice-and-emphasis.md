# 叙述口吻与强调

「认不清角色」和「重点难以像人那样语气变强」是同一个问题的两面：文章没有明确的说话人，所以既不知道该用什么身份说，也不知道该在哪里用力。

## 一、叙述者卡片

动笔前先认下这个身份：

> 一个刚读完这篇论文的人，正给同组的同伴讲。他手上摊着论文，讲的时候会翻到某一页说「你看这张表」。他已经读懂了，所以不犹豫；但他知道自己只读了这一篇，所以边界说得很清楚。

四个不是：

| 不是 | 症状 |
|---|---|
| 论文作者 | 说「我们提出」「本文贡献」 |
| 审稿人 | 评价「创新性不足」「实验不够充分」 |
| 客服 | 寒暄、「希望对你有帮助」、「如有疑问」 |
| 教科书 | 从盘古开天讲起，假装读者什么都不知道 |

这个身份决定了三件事：

- **敢下结论**：读懂了就用陈述句，不用语气词兜底。
- **说清边界**：只对自己读过的部分负责，没读到的直接说没读。
- **有现场感**：可以指图、指表、指某一行伪代码，而不是抽象地「论文指出」。

## 二、人称

中文技术写作默认省略主语，这是最自然的状态。

| 人称 | 用法 | 上限 |
|---|---|---|
| 省略 | 默认 | 无 |
| 你 | 讲读者会遇到的场景、给操作建议 | 每节一两次 |
| 我 | 交代阅读判断（「读到这里时我卡了一下」） | 全篇不超过三次 |
| 我们 | **不用**。指作者写「作者」，指读者写「你」 | 零 |

「笔者」「本文」都是论文腔，不要用来指文章自己。文章的主语应该是具体对象：FlashAttention、作者、这个算法、表 2。

## 三、禁用句式

| 禁用 | 为什么 | 改成 |
|---|---|---|
| 本文提出了一种…… | 文章自称，摘要腔 | 直接写对象和动作 |
| 我们可以看到 / 不难发现 | 对话式导航，替读者下判断 | 直接陈述 |
| 值得注意的是 | 空转，不增加信息 | 删掉，直接说那件事 |
| 综上所述 / 总的来说 | 模板收尾 | 写具体关系和边界 |
| 具有重要的理论意义和实用价值 | 空评价 | 写它改变了哪个数字或约束 |
| 希望对你有帮助 / 如有疑问 | 客服腔 | 删 |
| 让我们 / 接下来我们将 | 强行拉读者 | 直接进入内容 |
| 众所周知 | 掩盖没查的事实 | 给来源或删 |
| 显著提升 / 效果很好 | 形容词代替证据 | 换成数字和条件 |

注意：这些词不是风格评分，而是**结构信号**。出现「值得注意的是」，通常说明前一句没有把重点放对位置。

## 四、七种强调手法

「语气变强」不是加形容词，是让句子承担更多判断。以下七种按有效性排序。

### 1. 断言句独立成段

把一节的核心判断抽出来，单独成段，前后留白。读者的眼睛会自动停在这里。

> 整个算法只有一个不变量：每一行 Softmax 的分母，可以在没见过完整一行的情况下被增量维护。

### 2. 先结论，后推导

不要按论文顺序「背景 → 方法 → 所以」。先给判断，再解释为什么。读者带着结论读推导，理解成本低得多。

### 3. 用对比数字代替形容词

| 弱 | 强 |
|---|---|
| 显著减少显存访问 | HBM 读写从 40.3 GB 降到 4.4 GB |
| 大幅加速训练 | 训练时间从 21.0 天降到 6.9 天 |
| 效果很好 | 在 8×A100 上端到端快 13% |

### 4. 写具体后果，不写评价

| 弱 | 强 |
|---|---|
| 这个设计非常重要 | 去掉这一步，反向传播就拿不到完整的 P |
| 内存占用改善明显 | 基线在 40 GB A100 上先耗尽显存，它还能继续跑 |
| 对长序列很友好 | 序列从 1K 增到 4K，显存不随 N² 增长 |

### 5. 指出不变量或一句话机制

给读者一个可以带走的「骨架句」。它比任何总结都更能让人记住这篇论文。

> K/V 的同下标配对决定计算是否正确，内外循环顺序只决定复用哪一侧的数据。

### 6. 句长节奏

长解释之后接一个短判断。中文技术文章里，6–12 字的短句最有力量。

> 标准实现把 S 写回 HBM，再读出来做 Softmax，再写回 P，再读出来和 V 相乘。四次搬运，两次是 N² 大小。这就是全部问题。

避免每段都是「总—分—总」，那会让所有段落等重。

### 7. 重复主线词，不换同义词

主线概念（分块、在线 Softmax、重算、IO）在全文中保持同一个词。换「切块」「增量归一化」「重新计算」会让读者以为是四个东西。

## 五、慎用：对比句式

「不是 A，而是 B」在纠正误解时很有力，但连续使用会变成 AI 腔的排比。规则：

- 全篇最多两次。
- 只在读者**真的可能**持相反预期时用。
- 用完之后必须马上给证据，否则只是换个方式喊口号。

## 六、语气强度公式

> **强度 = 断言 + 证据 + 后果**

- 只有断言 → 口号
- 断言 + 证据 → 结论
- 断言 + 证据 + 后果 → 读者会记住

检验方法：把一句话里的形容词全部删掉。如果句子还成立，说明它本来就不需要那些词；如果不成立，说明你还没找到证据。

## 七、改写示例

### 示例一：论文腔 → 人话

**原句**

> 本文提出了一种 IO 感知的精确注意力算法，并通过大量实验验证了其有效性。

**改写**

> 先把结论放在前面：FlashAttention 算的还是同一个 softmax(QKᵀ)V，一个位置都没跳过。变的是这些中间结果放在哪里算、算完要不要写回显存。

### 示例二：平铺 → 有重点

**原句**

> FlashAttention 通过分块计算减少了显存访问，因此在实验中取得了较好的加速效果。

**改写**

> 它没有少算一次矩阵乘法。它只是不再把 N×N 的中间结果搬进搬出显存。图 2 里，计算量增加了 13%，HBM 读写降到约九分之一，耗时降到约六分之一。

### 示例三：罗列 → 后果

**原句**

> 论文还测试了长上下文任务，结果显示使用 FlashAttention 可以获得更好的性能。

**改写**

> 序列变长之后，收益不再只是快。图 3 右侧，需要保存完整 N×N 矩阵的基线在 40 GB A100 上先耗尽显存；FlashAttention 的注意力内存随序列长度近似线性增长，同一张卡能跑更长的上下文。

### 示例四：答疑腔 → 正文

**原句**

> 问：为什么 K/V 放在外循环？
> 答：因为这样可以复用 K/V，减少 HBM 读取。

**改写**

> 外层循环装的是键和值，内层是查询。这个顺序不改变计算结果，只改变谁被重复读取：一个 K/V 块装进片上之后，可以服务全部查询块；反过来则要为每个查询块重读整套 K/V。论文选前者，因为它的 IO 公式统计的正是这种复用方式。

### 示例五：连续段落推导 → 主干结论 + 折叠框一步一换行

**原句（连续段落塞满公式 + 单行长连等式）**

> 反向传播已知 $dO$，由 $O = PV$ 可知 $dV = P^{\mathsf T} dO$ 且概率梯度为 $dP = dO V^{\mathsf T}$；由 $P = \operatorname{softmax}(S)$ 可知分数梯度满足 $dS_{rt} = p_{rt}(dP_{rt} - \sum_u p_{ru} dP_{ru})$；最后由 $S = QK^{\mathsf T}$ 得到 $dQ = dS\,K$ 与 $dK = dS^{\mathsf T} Q$。其中 $D_r = \sum_{u=1}^{N} p_{ru} (dO_r v_u^{\mathsf T}) = dO_r \cdot (\sum_{u=1}^{N} p_{ru} v_u)^{\mathsf T} = dO_r \cdot o_r^{\mathsf T} = \operatorname{rowsum}(dO_r \odot o_r)$。

**改写（主干只留核心机制，分步求导链收进 `::: details` 并一步一换行）**

> 反向传播已知输出梯度 $dO$，求 $dQ, dK, dV$ 的每一步都依赖概率矩阵 $P$。为了不在 HBM 中保存 $N\times N$ 的 $P$，算法利用两条代数性质在片上按块重算：
>
> 1. **由全局行状态 $(m_i, \ell_i)$ 一步恢复概率块**：重算局部打分 $S_{ij} = Q_i K_j^{\mathsf T}$ 后，直接由 $P_{ij} = \operatorname{diag}(\ell_i)^{-1}\exp(S_{ij} - m_i)$ 得到精确全局概率。
> 2. **用前向输出 $O$ 消除跨块求和**：Softmax 反向公式中的行内加权和 $D_r = \sum_{u=1}^{N} p_{ru}\, dP_{ru}$ 可直接化简为前向输出与输出梯度的逐元素乘积行和 $D_r = \operatorname{rowsum}(dO_r \odot o_r)$，无需拼出整行 $P$ 和 $dP$。
>
> ::: details 点击展开：反向传播梯度链与行内点积 $D_r$ 的分步推导
> 1. **由 $O = PV$ 求值梯度与概率梯度**：
>    $$dV = P^{\mathsf T} dO, \qquad dP = dO\,V^{\mathsf T}$$
> 2. **由 $P = \operatorname{softmax}(S)$ 求分数梯度**（第 $r$ 行、第 $t$ 列）：
>    $$dS_{rt} = p_{rt}\!\left(dP_{rt} - D_r\right), \qquad D_r := \sum_{u=1}^{N} p_{ru}\, dP_{ru}$$
> 3. **由 $S = QK^{\mathsf T}$ 求查询梯度与键梯度**：
>    $$dQ = dS\,K, \qquad dK = dS^{\mathsf T} Q$$
> 4. **化简行内求和项 $D_r$**：
>    $$
>    \begin{aligned}
>    D_r &= \sum_{u=1}^{N} p_{ru}\, dP_{ru} &&\text{（Softmax 反向行内求和定义）} \\
>    &= \sum_{u=1}^{N} p_{ru} \left(dO_r v_u^{\mathsf T}\right) &&\text{（代入第 1 步 } dP_{ru} = dO_r v_u^{\mathsf T}\text{）} \\
>    &= dO_r \cdot \left(\sum_{u=1}^{N} p_{ru} v_u\right)^{\mathsf T} &&\text{（提出与求和下标 } u \text{ 无关的 } dO_r\text{）} \\
>    &= dO_r \cdot o_r^{\mathsf T} &&\text{（括号内即前向输出定义 } o_r = \sum_u p_{ru} v_u\text{）} \\
>    &= \operatorname{rowsum}(dO_r \odot o_r) &&\text{（改写为逐元素乘积的行和）}
>    \end{aligned}
>    $$
> :::

## 八、自检

- [ ] 全文没有「本文」「笔者」「我们」
- [ ] 每节有一个断言句，且单独成段
- [ ] 形容词已经换成数字、条件或后果
- [ ] 主线词没有换同义词
- [ ] 「不是 A 而是 B」不超过两次
- [ ] 随机抽三段，删掉形容词后仍然成立
- [ ] 没有任何把多步公式推导用分号串在一段话里的写法
- [ ] 读起来像一个人在讲，不像一份报告在念
