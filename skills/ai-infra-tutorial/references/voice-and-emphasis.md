# 叙述口吻与强调

教学文章要求**语气亲切、用词严谨**——既不能像学术论文摘要那样冷硬疏离，也不能像客服寒暄或百科辞典那样从盘古开天讲起、满篇空洞修饰词。

## 一、叙述者卡片

动笔前先认下这个身份：

> 一个已经在机器上跑通实验、把底层数据流和源码调用链理顺的 AI Infra 工程师，正带着同组新人顺着示意图和最小示例把机制过一遍。讲的时候会指着图说「对照上方步骤 2」、会先给精确定义再讲工程代价；已经查证或实测过的地方下结论果断，没跑过或受条件限制的地方也把边界摊开说透。

四个不是：

| 不是 | 症状 |
|---|---|
| 论文作者 | 说「我们提出」「本文贡献」 |
| 审稿人 | 空泛评价「该设计非常巧妙」「具有深远意义」 |
| 客服 | 寒暄、「希望对你有帮助」「如有疑问欢迎留言」 |
| 教科书流水账 | 把不需要的先修史从头抄一遍，堆砌术语却不讲系统后果 |

## 二、人称

中文技术教学默认省略主语，读起来最利落自然。

| 人称 | 用法 | 上限 |
|---|---|---|
| 省略 | 默认 | 无 |
| 你 | 提示读者动手验证、遇到常见误区时对话 | 每节一两次 |
| 我 | 极少使用，仅交代排查或阅读判断 | 全篇不超过两次 |
| 本文 / 笔者 | **禁用**。主语直接写具体组件、算法、实验结果或读者 | 零 |

## 三、禁用句式

| 禁用 | 为什么 | 改成 |
|---|---|---|
| 本文介绍 / 本文提出 / 笔者认为 | 论文腔自称 | 直接写对象和动作 |
| 我们可以看到 / 不难发现 | 对话式导航，替读者下判断 | 直接陈述机制或结果 |
| 值得注意的是 | 空转，不增加信息 | 删掉，直接说那件事 |
| 综上所述 / 总的来说 | 模板收尾 | 写具体系统因果和适用边界 |
| 具有重要的理论意义和实用价值 | 空评价 | 写它改变了哪个显存、带宽或延迟指标 |
| 希望对你有帮助 / 如有疑问 | 客服腔 | 删 |
| 让我们 / 接下来我们将 | 强行拉读者 | 直接进入内容或指明实验动作 |
| 众所周知 | 掩盖没核对的事实 | 给一手来源或直接删掉 |
| 显著提升 / 效果很好 | 形容词代替证据 | 换成数字、倍率、公式或条件 |

## 四、七种强调手法

「重点突出」靠的是结构排布与信息密度，不是堆叠感叹号或五颜六色的字体。

### 1. 断言句独立成段

每节的核心判断抽出来，加粗并单独成段，前后留白。读者扫读时眼睛会自动停在这里。

> **模型在推理阶段每生成一个词元，都要把数十亿权重从显存搬运到计算核心做一次完整前向运算；因此词表压缩率直接决定了单次服务的显存占用与生成耗时。**

### 2. 先结论，后展开

先给判断，再带读者顺着图和代码验证为什么。带着结论读细节，认知负担低得多。

### 3. 用对比数字与公式代替形容词

| 弱 | 强 |
|---|---|
| 中文切分效率很低，消耗很多额外显存 | 同一段 500 字中文，多语言大词表约需 290 个 Token，早期 32K 英文主导词表需 740 个 Token，KV Cache 与生成耗时膨胀至 2.55 倍 |
| 推理显存比训练小很多 | 推理冻结全部权重，省去梯度、优化器状态与反向激活值，显存主要由只读权重与 KV Cache 构成 |

### 4. 写具体系统后果，不写评价

| 弱 | 强 |
|---|---|
| Tokenizer 设计非常重要 | 一旦汉字被拆成 3 个字节碎片，相同上下文窗口能容纳的有效中文信息量就会缩水六成以上 |
| 多模态接入带来了挑战 | 高清图片切成数百个 Visual Token 后会直接拉长 Prefill 耗时并迅速占满 KV Cache |

### 5. 给出可带走的机制骨架句

> 训练是「前向 + 算损失 + 反向 + 更新权重」的闭环；推理冻结权重，只走前向。

### 6. 句长节奏

一段长机制拆解之后，接一句 8–16 字的短判断收住节奏，避免所有段落等长平铺。

### 7. 重复主线词，不换同义词

主线核心概念（如 `词元（Token）`、`键值缓存（KV Cache）`、`预填充（Prefill）`、`解码（Decode）`）在全文固定用同一个词，不要中途随意切换别名。

## 五、慎用对比句式与语气强度公式

- 「不是 A，而是 B」全篇最多两次，且只用于纠正读者常见误区，用完紧跟机制或数字证明。
- **强度 = 断言 + 依据（一手规范 / 实测 / 算式）+ 系统后果**。删掉一句里的形容词，如果句子立刻塌了，说明缺的不是修饰词，而是证据或后果。

## 六、自检

- [ ] 全文没有「本文」「笔者」「我们可以看到」「值得注意的是」「综上所述」
- [ ] 每节有一个粗体断言句，且单独成段
- [ ] 形容词已替换为实测数字、理论算式或具体系统后果
- [ ] 同一技术对象全文只有一个固定译名
- [ ] 没有用分号在自然段内串写多步推导
