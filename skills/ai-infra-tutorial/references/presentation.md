# 标题、形式、公式与术语规范

这份文件统一规定教学文章的标题层级、多形式承载分工、MathJax 渲染伪代码、一步一换行公式推导、克制视觉引导与术语定义格式。

## 一、标题系统与维度拆解原则

标题采用**简洁短语 + 维度显式拆解 + 适当多级展开**：H2 锚定技术模块或阶段，H3 把同一技术的「**原理/简介 $\to$ 典型技术/机制 $\to$ 应用/边界**」拆开，具体并列方法下沉为 H4；具体的结论判断交给紧随小节之后的**粗体断言句**。

| 层级 | 作用 | 句式要求 | 例子 |
|---|---|---|---|
| H1 | 文章总主题 | 简短名词短语 | 执行与解码加速 / KV Cache 与显存调度 |
| H2 | 模块或核心技术 | 短名词短语（≤ 14 字为佳） | Decode 阶段的瓶颈诊断 / 算子融合 / CUDA Graphs / 投机解码 |
| H3 | 技术的**单个认知维度** | `xxx原理` / `xxx简介` / `典型xxx方式` / `xxx应用` / `xxx边界` | 算子融合原理 / 典型算子融合方式 / 推理引擎中的 CUDA Graph 应用 |
| H4 | 具体**并列子方法或子机制** | 单个技术名或极短名词短语 | Memory-Bound 融合 / Epilogue 融合 / Medusa / EAGLE-3 |

### 预算与五条硬规则

1. **短标题与非复杂句**：H2 不超过 18 字、H3 不超过 18 字（英文术语计数宽松放宽至 28 字符），严禁用复杂动宾/因果长句当标题；非答疑小节不用问句标题。
2. **维度拆解与原理前置**：介绍任何一项具体技术时，必须在 H3 中明确拆开「定义/原理 $\to$ 方法/机制 $\to$ 应用/边界」不同维度，**原理或简介必须排在第一个 H3**，不能把原理和作用混在同一个模糊标题里。
3. **多层级展平具体方法**：全篇 `1` 个 H1，`4–8` 个 H2（含小结与延伸阅读），H3 不超过 `18` 个；当某个 H3 介绍多种并列实现方式或代表技术时（如 `典型投机解码技术`、`推理引擎中的 CUDA Graph 应用`），**为每个具体方法单开一个 H4**（如 `#### Medusa`、`#### EAGLE-3`），总标题数控制在 `30` 个以内。
4. **父子标题之间必须写引导段**：H1 与首个 H2 之间、**每个 H2 与其下属首个 H3 之间**不能直接空接，必须先写 1–3 句引导段点出问题、对比反差或抛出思考题（例如在 `## Decode 阶段的瓶颈诊断` 下先对比 Prefill 与 Decode 的表象再问「那么 Decode 阶段的瓶颈主要在哪？」，随后进入第一个 H3）。
5. **标题与导语硬件脱敏**：所有标题（H1/H2/H3/H4 与 `::: details` 标题）均严禁写入测试显卡型号（如 `RTX 5070`、`RTX 4090`、`A100`）。

**反面教材（禁止出现以下三类写法）**：

- ❌ **维度混杂 + 句式过长**：`### 算子融合把多次显存往返压缩进片上缓存并受寄存器限制`（原理、作用、边界混成一句长标题，读者无法拆分浏览）
- ❌ **缺原理前置与子方法平铺**：`## 算子融合` 下直接写 `### SwiGLU 实践`、`### CUDA Graphs 的 Bucketing 分桶`（未先立住 `算子融合原理` / `CUDA Graphs 简介`，直接跳入局部细节）
- ❌ **H2 与首个 H3 之间无引导段**：`## Decode 阶段的瓶颈诊断` 下一行直接跟 `### Prefill、Decode 的算术强度对比`，缺少起承转合的提问引入。

## 二、形式选择

| 内容 | 用什么 | 不要用 |
|---|---|---|
| 一句补充提醒、易错前提 | `::: tip` / `::: warning` 容器，或脚注 `[^1]` | 硬塞进主干打断节奏 |
| 完整可运行代码、多步数学/显存推导、MathJax 伪代码、手算算例、环境命令细节 | `::: details 点击展开：<具体内容>` 折叠容器 | 平铺在主干阻塞阅读，或在折叠框内嵌套 `:::` |
| 两个以上对象、同一组维度对比 | 表格（数字右对齐，文字左对齐，表后加判断句） | 连续段落罗列 |
| 算法伪代码 | `>` 引用块 + 有序列表 + `&emsp;` 缩进 + `$...$` MathJax 公式（放入 `::: details`） | ` ```text ` 纯文本代码块裸写数学符号 |
| 架构、数据流、阶段对比、布局 | 自绘 SVG（内联属性 + 渲染检查）或核实后的一手原图 | Mermaid（站点未装配插件）或简陋 ASCII 框图 |
| 主干核心结论公式 | `$$...$$`，按 `(1), (2), ...` 连续编号（每小节最多 1 个） | 折叠框内公式抢占主干连续编号 |
| 两步及以上公式推导或算式 | `aligned` 块（一等号一换行 + 右侧 ≤ 12 字依据）或分步有序列表 | 自然段分号串推、单行多等号 |
| 关键判断与核心视觉焦点 | 粗体断言句（单独成段）+ 单一暖底 `<mark>` 高亮（每节 1–2 处） | 多色文字混排（`<span style="color:...">`）、大面积加粗、中文斜体 |

## 三、MathJax 渲染版伪代码规范

所有正式算法伪代码统一收进 `::: details 点击展开：算法 N（...）`，严禁用 ` ```text ` 纯文本代码块导致上下标或希腊字母无法渲染。统一采用引用块卡片形式：

```markdown
> **算法 1：BPE 词表构建流程**（来源：[Sennrich et al., 2016](https://arxiv.org/abs/1508.07909)）
> - **输入**：原始语料 $D$，目标词表容量 $V$
> - **输出**：合并规则列表 $M$ 与词表 $\mathcal{V}$
>
> 1. 初始化词表 $\mathcal{V}$ 为全部基础字节（$256$ 个基础符号）
> 2. **while** $|\mathcal{V}| < V$ **do**
> 3. &emsp;统计语料中相邻符号对 $(a, b)$ 的出现频次
> 4. &emsp;选取最高频符号对 $(a^*, b^*)$ 合并为新符号 $c = a^* b^*$
> 5. &emsp;将 $c$ 加入 $\mathcal{V}$，将合并规则 $(a^*, b^*) \to c$ 追加至 $M$
> 6. **end while**
> 7. **return** $M, \mathcal{V}$
```

## 四、公式与步骤推导：一步一换行

1. **禁止自然段内分号串推**：凡两步及以上代数变换、求导链或数值代入，必须拆分为有序列表或 `aligned` 块，每步独立一行。
2. **列表项单行单动作**：每个列表项内只写一个计算或执行动作，禁止用分号并列多个赋值。
3. **多步等式一等号一换行**：两个以上连续变换等号放进 `$$\begin{aligned} ... \end{aligned}$$`，用 `\\` 换行并在行末用 `&&\text{（依据，≤12字）}` 对齐标明变换理由。
4. **精确化简（`=`）与数值估算（`\approx`）分行写**：先写精确展开行，再另起一行写 `&\approx ...`。

## 五、用词、比喻与术语纪律

### 1. 少用比喻

比喻不能替代底层机制解释。**禁用以下词承担核心论证**：`流水线`、`大脑`、`积木`、`喂给`、`串起来`、`魔法`、`黑盒`（注：仅指 `Instruction Pipeline`、`Pipeline Parallelism` 等专有名词时需写成 `指令流水线`、`流水线并行` 或 `流水线调度` 并解释含义）。先用机制和数据结构讲清，不用泛化类比蒙混过关。

### 2. 术语首次出现必解释

对于专业词汇、领域缩写或容易误解的概念，**在文中首次出现的位置立刻解释**，格式为：

> **中文术语（English Full Name, ABBR）**：用一到两句话说明它是什么、在系统里起什么作用。

如果解释超过三行，可紧接主干放入简短注记块或折叠框。重要名词首次出现附一手来源链接（官方文档、原论文、标准仓库），全文不链二手博客，全篇外链控制在 3–8 个左右。

### 3. 不自造术语、全程同一译名

不把动词硬名词化（如「分块化」「张量化」）；同一个对象全文固定使用同一个中文名或缩写，绝不在前文叫「键值缓存」、后文换成「KV 记忆池」。
