# 资源指南、一手核对与 GPU 实测

教学文章最怕两件事：一是把二手博客的模糊转述当成原理，二是没跑过代码却编出看似精确的耗时和显存数字。这份文件规定「先借结构、再核一手、按需实测、无条件诚实降级」的写作工作流。

## 一、写作前必查资源指南

写作任何 AI Infra 主题前，先读取本技能自带的资源索引：

```text
references/source-index.md
```

### 三步查证法

1. **按专题定位「先读」教程，借鉴结构编排**：
   - 依据文章所属板块（入门、编程前置、推理与服务、GPU 与算子、训练与优化、分布式并行）定位对应行。
   - 打开「先读」栏列出的优质中文/英文课程（如 `zero-to-sglang`、`AIInfraGuide`、`CS336`、`Scaling Book`、`Ultra-Scale Playbook` 等），观察作者如何切入新手直觉、先讲哪个概念再引出哪个瓶颈、用什么小例子把抽象机制落地。
   - 同时可参考站点已有成稿范例（如 `docs/guide/orientation/llm-overview.md`）的节奏：概念定义 → 贯穿小例 → 架构图逐号解说 → 系统成本影响 → 对照表 → 小结与延伸阅读。
   - **借结构，不抄正文**：只提取认知顺序与问题拆解角度；文本、图解与实验示例必须自己重新组织并附出处链接。
2. **用「核对」栏回溯一手事实**：
   - 同行教程随时间会过期。涉及公式定义、CLI 参数、默认开关、API 行为、源码调用链时，**必须打开「核对」栏的原论文、官方文档或指定版本源码 tag 验证**。
   - 论文负责解释原始设计与动机；框架文档和源码负责说明当前版本的真实实现。两者不一致时，正文写明所依据的版本并说明差异。
3. **建立临时查证笔记**：
   - 在临时目录记下本篇要用到的三类条目：① 本篇要解释的核心机制与先修依赖；② 核对过的一手链接与版本号；③ 计划用同一小例子展示的数据/数值。

## 二、断言阶梯（教学版）

| 级别 | 证据来源 | 怎么写 | 要不要限定条件 |
|---|---|---|---|
| **L1 一手规范/源码** | 原论文、官方文档、源码实现 | 直接陈述，句末附一手来源链接或版本 | 涉及版本差异时注明版本号 |
| **L2 实机实测** | 在本地或远程 GPU 机实际跑出的输出/profiler 数据 | 陈述结果 + 写明硬件、软件版本、输入规模与基线 | 条件本身就是限定，缺条件不放数字 |
| **L3 理论估算/机制推导** | 由模型参数、精度字节数、通信量公式算出的数值 | 明确标出「按……公式推算」，并在正文或折叠框写出完整算式 | 需要，不能写成实测结果 |
| **L4 未实测/未覆盖** | 未跑实验、无可用 GPU、官方未公布 | 直接写「未在实机验证，按机制预期……」或留「待实机验证项」 | 这是事实边界，禁止用「可能」「大概」软化 |

### 禁用与慎用词

- **直接禁用**（除非引用原文）：可能、或许、也许、似乎、大概、不能确定、难以断言、有待进一步研究、尚无定论。
- **慎用**：显著、大幅、极大、非常、至关重要——把位置让给具体数字、倍率或对比条件。

## 三、GPU 实测与降级规范

当教程涉及显存实测、Tokenizer 压缩率对照、PyTorch 张量 stride/view 验证、CUDA/Triton kernel 计时、vLLM/SGLang 并发压测或多卡通信带宽测试时，优先在本地可用 GPU 或用户配置的远程 GPU 实验机上完成实机验证。

### 实验环境与目录隔离

- **实验环境发现**：先检查当前本机是否具备可用 NVIDIA GPU（`nvidia-smi`），或检查当前工作区规则文件（如 `AGENTS.md`、`GEMINI.md`、`CLAUDE.md`）及用户对话是否提供了远程 GPU 实验机连接方式。
- **独立试验区**：在实验机上按文章 slug 建立独立临时子目录（如 `~/compute_factory_lab/<topic-slug>/`），不要在公开站点目录 `docs/` 下直接存放临时测试产物。

### 实测记录硬要求

1. **先查环境再跑数**：每次实验前记录 `nvidia-smi` 输出的 GPU 型号与显存容量、CUDA 版本、Python/PyTorch/推理框架版本号。
2. **控制变量与预热**：计时测试前必须做 warmup 并取多轮均值；对照试验保持模型权重、精度（如 `bf16` / `fp16`）、序列长度与 batch size 一致。
3. **保留可复现命令并注释解读（去私有路径与去硬件绑定）**：
   - 把完整脚本或拓展命令收进 `::: details 点击展开：<实测源码/命令与关键输出>`，或放入文末「入门动手实战」章节。
   - **禁止暴露作者私有路径**：写进文章的命令、路径与注释不得出现 `/home/<真实用户名>/...`、`C:\Users\<真实用户名>\...` 或内网 IP 等实验机私有信息，需替换的路径一律改用通用占位路径（如 `/path/to/models/...`、`~/venvs/...`）并提醒读者按本机环境修改。
   - **标题与正文中段硬件隔离**：不得把实测所用显卡型号（如 `RTX 5070`、`A100`）写进章节标题、折叠框标题、文章开篇导语或纯原理概念段落中；**仅在交代实验输出环境说明或实测结果对比表口径栏时**客观注明采样 GPU 型号与软件版本。
   - 代码块内**必须对关键参数、占位路径及难点加中文注释**；一个步骤一个代码块，每步下方紧跟要点和解释；原始输出过长时用 `...` 省略冗余行，只保留关键指标行，且**输出后必须紧跟结果分析与字段核对**，不得只丢出代码和裸输出。
   - 表格旁写明观测口径（例如 `torch.cuda.max_memory_allocated()` 还是 `nvidia-smi` 进程总占用）。
4. **理论与实测对账**：如《大模型概览》及《第一次实验》所要求，先算理论值（如参数量 × 每元素字节数），再报实测值，并解释框架额外缓冲、CUDA 上下文或内存对齐导致的偏差。

### 无 GPU 环境时的降级规则（不阻塞原则）

当本机无可用 GPU 且未配置或无法连接远程 GPU 实验机时：

1. **立即降级并照常完成写作**：不得卡死在重试循环中，也不得拒绝写文章。
2. **严禁编造实测结果**：绝对不能根据经验虚构一组「某显卡实测耗时 12.3 ms」写进表格。
3. **用 L3 核算 + L4 预期替代**：
   - 将性能讨论改为可验算的**理论推导**（如参数/KV Cache 显存公式、FLOPs 与访存带宽比值估算），并明确标注「理论核算」。
   - 将原本用于实证的实验步骤写成可执行的实验指导 + 「预期输出格式（待在具备 CUDA GPU 的环境中实机运行验证）」，保证读者拿到文章即可自行跑通校验。
