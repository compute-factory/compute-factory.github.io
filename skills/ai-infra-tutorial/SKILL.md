# AI Infra 教学文章写作

## 核心判断

**优秀教程的结构靠借鉴打磨，内容与数字必须回溯一手源码、官方文档、原论文或实机实测；主干讲透心智模型与系统因果，折叠框承载完整代码、长表与多步推导。**

教学文章的读者目标不是「复述一篇论文」，而是建立可迁移的系统心智模型，并知道参数在硬件和代码里如何落地。采用「**主干极简成文 + `::: details` 折叠深读**」双层结构：
- **不展开任何折叠框时**：外部主干是一篇**语气亲切、用词严谨、逻辑环环相扣的完整教程**，围绕一个贯穿全文的小例子讲清核心定义、机制不变量、系统成本与工程折中，配合克制的 `<mark>` 暖底高亮与清晰的矢量架构图。
- **点击下拉展开时**：深度读者可就地查看完整可运行代码、多步代数/显存核算推导、MathJax 渲染版算法伪代码与实测复现命令。

## 七个失败模式

| 症状 | 机制 | 详见 |
|---|---|---|
| 照搬他人教程顺序或数字，版本与参数对不上 | 资源索引双轨查证（先读借鉴结构，再回一手核对） | `references/sources-and-lab.md`、`references/source-index.md` |
| 实测数字来路不明，或无 GPU 环境就编造性能表 | GPU 实测规范 + 无条件降级为理论估算/待验证 | `references/sources-and-lab.md` |
| 全篇纯文字堆砌架构与请求流转，读者抓不住数据路径 | 主动生成 SVG/示意图 + 渲染后核查文字不越框 | `references/structure-and-diagrams.md` |
| 「可能」「大概」满篇、论文腔/客服腔、每段等重 | 断言阶梯 + 叙述者卡片 + 暖底 `<mark>` 克制引导 | `references/voice-and-emphasis.md`、`references/presentation.md` |
| 主干塞满长脚本/推导墙，或伪代码未渲染、推导挤成一行 | 主干极简成文 + `::: details` 收纳 + 一步一换行 | `references/structure-and-diagrams.md`、`references/presentation.md` |
| 穿插命令+原始输出却只有裸代码块、缺少注释与结果解读 | 代码块注释 + 关键输出截选（`...` 省略冗余）+ 结果分析 | `references/structure-and-diagrams.md`、`references/sources-and-lab.md` |
| 学完原理却没有从零环境配置到跑通验证的入门抓手 | 除原理概述外，文末必设入门级「动手实战」章节 | `references/structure-and-diagrams.md` |

## 工作流

### 0. 定读者与教学落脚点

- **目标读者**：默认会写 Python、跑过 PyTorch 基础代码，但尚未建立该专题的系统级心智模型。
- **开篇立锚**：导语交代「为什么在 AI Infra 视角下需要弄懂这件事」，点明它决定后续哪类显存、带宽、延迟或并行折中。
- **贯穿示例**：选定一个最小可追踪的具体例子（如同一段中英文分词、同一张小张量 `shape/stride`、同一个 70B 模型的显存账本核算），从头贯穿到尾。

### 1. 查阅资源指南（借鉴结构，一手核对）

动笔前先读取本技能内置的资源索引文件：`references/source-index.md`。

1. **借鉴结构与讲法**：按索引中的章节或关键词定位「先读」栏列的优质教程（可参考站点已成稿的优质范例，如 `docs/guide/orientation/llm-overview.md` 的层次推进与图解配合方式），提取适合新手建立直觉的认知顺序、容易卡住的前置盲区。
2. **回溯一手核对**：按索引「核对」栏打开原论文、官方文档或对应版本源码，核准概念定义、API 名称、默认值与限制条件。**同行教程只提供结构灵感，不能直接当作事实证据。**

### 2. GPU 实测（按需执行，无环境即诚实降级）

若教程涉及真实显存占用、Tokenizer 切分比、算子耗时、带宽/吞吐对比、框架行为验证等实测需求，优先使用可用的本地 GPU 或用户在环境/规则中提供的远程 GPU 实验机完成实测：

- **实验目录**：在本地或远程实验机上使用独立工作目录（如 `<lab-workspace>/<topic-slug>/`），避免污染项目源码目录。
- **记录规范**：实测结果必须写明 GPU 型号、驱动/CUDA/框架版本、模型/输入规模、对比基线与复现命令。
- **降级规则**：若当前环境无可用 GPU 或远程实验机无法访问（网络超时、无凭据或缺少依赖），**不阻塞写作，也不编造实测数字**；照常编写教程，改用带完整算式的理论估算（标记推导依据），并将原本计划实测的项写为「预期现象」或「待实机验证步骤」。

### 3. 主动配图（官网高清真图 + 站点同款柔和矢量 SVG）

遇到系统架构、数据流水线、计算前后向对比、张量布局、并行切分、调度状态机时，**必须按「官方真图 + 站点同款柔和矢量 SVG」双轨配图**：

- **硬要求（≥ 1 张官方高质量网络图片）**：每篇教程必须包含 **至少 1 张来自官方网站、官方文档或原论文的高质量真实图片**（如 NVIDIA 官方博客/Nsight 截图、PyTorch 官方文档图、vLLM/SGLang 架构图或原论文图表）。将原图下载保存至文章对应图片目录，图注中必须注明一手来源链接。
- **自制矢量图硬规则（外圈暖黄光晕 + 站点字体栈 + 400/700 字重，含 Few-Shot 母版）**：自制架构图与流程图必须使用**内联属性矢量 SVG**（禁用 `<style>` 块，保证跨渲染器文字锐利零错字），直接遵循 `references/structure-and-diagrams.md` 中的 **SVG Few-Shot 母版** 与硬规则：
  1. **画布比例**：`viewBox="0 0 1120 620"`（16:9 横向宽屏，`width / height >= 1.4`）；
  2. **外圈暖黄光晕**：底层暖象牙黄画布 `#fffdf7` 留出 `18 px` 边带 + 白色大圆角主卡片（`rx="22"`、`stroke="#ebe3d0"`、`filter="url(#soft-shadow)"`）；
  3. **字体栈与字重**：正文统一完整声明 `Inter, HarmonyOS Sans SC, PingFang SC, Noto Sans SC, Noto Sans CJK SC, Microsoft YaHei, sans-serif`，等宽标识用 `JetBrains Mono, Cascadia Code, SFMono-Regular, Consolas, monospace`，**字重严格只用 `400` 与 `700`**（严禁 `600` 触发部分平台字体合成发虚）；
  4. **圆润柔和**：内部阶段卡 `rx="18"`、`#d9d0bd` 柔边 + 低饱和粉彩节点 + `stroke-linecap="round"` 弯折箭头。
- **图文强绑定与渲染检查硬规则**：正文按图中区域、编号或颜色路径逐步讲解。每张自制 SVG 必须以原尺寸无头渲染为 PNG 并看图实测检查：确认外圈暖黄光晕完整、无文字越框/重叠、无箭头穿字、无发虚；发现问题立即修改并重检。

### 4. 撰写

按 `references/structure-and-diagrams.md`、`references/voice-and-emphasis.md` 与 `references/presentation.md` 写：

- **术语先定义后使用**：首次出现的术语必须紧跟解释（`中文（English, ABBR）` + 一句话定义；较长说明可用注记块或折叠框）。
- **标题短而清晰，按维度拆解并允许子方法下沉**：H2 锚定技术模块（如 `算子融合`、`CUDA Graphs`、`投机解码`）；H3 将同一技术的**原理/简介、典型方式/机制、应用与收益边界**拆开，且原理/简介必须排在最前；具体并列方法可下沉为 H4（如 `#### Memory-Bound 融合`、`#### Epilogue 融合`），让读者仅看目录即可把握逻辑脉络。H1 与第一个 H2 之间、每个 H2 与其首个 H3 之间必须先写 1–3 句引导段抛出问题。
- **测试硬件只出现在实验环境段落**：导语、概念原理与标题中严禁提及测试机器的具体显卡型号和本地版本号（如 `RTX 5070`），仅在实测环境说明与观测口径处客观交代采样硬件与版本。
- **命令与原始输出必带注释和分析**：凡正文中或 `::: details` 内穿插「代码/命令 + 原始输出」拓展内容，代码块中必须对关键参数、难点和路径加中文注释，原始输出后必须紧跟关键指标解读与结果分析，严禁只贴裸代码和裸输出。
- **文末设入门实战章节（原理概述除外）**：除纯粹的全局原理概述/导论文章（如《大模型概览》《AI Infra 概览》《分布式并行概览》）外，每篇教学文章在 `## 小结` 前必须包含一个入门级实战章节。只默认读者具备基础 CUDA 与 Python 环境，推理框架或代码库（如 vLLM、SGLang、CUTLASS）必须作为独立步骤给出完整下载与安装命令；一个步骤一个代码块，每个步骤代码块下方必须写出要点与解释；编写源码文件时让读者新建目录与文件并单独给出语言代码块（禁止使用 `cat << 'EOF' > ...` 写入文件）；禁止暴露作者本机或远程实验机私有路径（需要修改的路径一律用通用草拟路径并提醒读者按本机环境修改）；标题中严禁出现具体显卡型号。
- **推导一步一换行**：严禁用分号在自然段或单条列表项内串联多步推导，严禁单行长连等式；多步变换放进 `aligned` 块一等号一换行并附不超过 12 字的右侧依据；精确式（`=`）与数值近似（`\approx`）分行写。
- **克制视觉引导**：每小节只在 1–2 个最核心的结论或关键数据上使用 `<mark>...</mark>` 暖底高亮，严禁多色内联字体与大面积加粗。
- **收束结构**：正文末尾设 `## 小结`（或 `## 结论`）与 `## 延伸阅读`（给出官方文档、原论文、源码仓库及学习课程的一手链接）。

### 5. 核对与校验

1. **不展开连读测试**：收起所有 `::: details`，从头通读主干，确认因果闭环、无未定义符号、阅读流畅。
2. **图片渲染核查**：确认所有自绘 SVG / 图片路径正确且经渲染检查无文字出框。
3. **运行脚本校验**：执行 `node scripts/check-tutorial.mjs <教程.md> [--strict]`（从仓库根目录运行时为 `node skills/ai-infra-tutorial/scripts/check-tutorial.mjs <教程.md> --strict`）。脚本自动检查禁用口吻、标题结构、比喻词、一步一换行、`::: details` 规范、私有路径泄漏、图片存在性与伪代码格式。

### 6. 落地与发布

见 `references/site-publishing.md`。默认先在工作区完成 Markdown 与配套图片保存；需要合入站点上线时，按站点目录约定放入 `docs/guide/<section>/<slug>.md` 与 `docs/public/images/<section>/<slug>/` 并运行构建验证。

## 硬规则

1. **先查指南再写**：写作前必查 `references/source-index.md` 借鉴同行教程编排，并用一手文档/源码/论文核对结论。
2. **实测诚实降级**：有本地或远程 GPU 环境则实测并写清环境条件；无实测环境则照常写作并标明理论核算或预期现象，严禁编造实测数据。
3. **官方真图必配、柔和矢量图必遵字体与暖光框硬规则**：每篇文章必须包含 **1 张以上来自官网/官方文档/原论文的高质量真实图片**（本地存图并附一手来源图注）；自制架构流程图必须按 `references/structure-and-diagrams.md` 的 Few-Shot 母版生成 **16:9 横向宽屏柔和矢量 SVG**，严格执行**外圈 `#fffdf7` 暖黄光晕底板 + `rx="22"` 白卡 `#ebe3d0` 柔边阴影、完整站点中英字体栈、仅使用 `400`/`700` 字重（禁 `600`）、内联属性（禁 `<style>`）**，插入前必须渲染 PNG 并看图核查无越框或遮挡。
4. **术语用前必解释**：重要名词首次出现给出中文、英文全称、缩写、一句话定义与一手来源链接，全文保持同一译名。
5. **主干极简独立成文**：不展开 `::: details` 时主干必须自洽闭环；完整脚本、长推导、伪代码与扩展算例统一收进 `::: details 点击展开：<具体内容>`。
6. **断言句与阶梯**：每节开头或结尾有粗体断言句单独成段；不确定性写进条件和边界，禁用「可能」「或许」「大概」等模糊兜底词。
7. **禁用自称与空话**：不用「本文」「笔者」；禁用「值得注意的是」「综上所述」「希望对你有帮助」等论文/客服腔。
8. **标题短句化、按维度拆解与硬件脱敏**：H1 唯一；H2 四到八个（用简短技术模块名或阶段名）；H3 不超过十八个，必须按「简介/原理 $\to$ 典型技术/机制 $\to$ 应用/边界」维度拆开，且原理绝对前置；具体并列技术可用 H4 展开（如 `#### Medusa`、`#### EAGLE-3`）；所有标题（含折叠框标题）简短清晰，不用复杂长句，非答疑不用问句，严禁出现测试显卡型号；H1 与首个 H2、每个 H2 与其首个 H3 之间必须写引导段提出问题（详见 `references/presentation.md` 标题 Few-Shot 示例）。
9. **伪代码必须 MathJax 渲染**：严禁用 ` ```text ` 裸写伪代码符号，统一用 `>` 引用块 + 有序列表 + `&emsp;` 缩进 + `$...$`。
10. **推导一步一换行**：禁止自然段或单条列表项内分号串推、禁止单行多等号、禁止 `=` 与 `\approx` 同行。
11. **克制视觉引导与少比喻**：每节 `<mark>` 不超过 2 处，禁用 `<span style="color:...">`；禁用「流水线/大脑/积木/喂给/魔法/黑盒」代替机制解释。
12. **无 AI 署名**：文章正文、注释与后续提交记录不加 AI 协助声明或 `Co-Authored-By`。
13. **一步一代码块、去隐私路径、硬件信息隔离与实战完整性**：穿插命令/源码与原始输出时必须注释关键参数并分析输出含义；本机/远端硬件型号与软件版本只允许出现在「实验环境说明 / 实测口径」处，禁止写入导语和原理段落；除原理概述类文章外，文末均须包含面向初学者的入门实战章节——只默认读者有基础 CUDA 与 Python，框架/仓库（如 vLLM）必须给出完整下载安装命令；禁止用 `cat << 'EOF'` 写文件，改为明确文件名并单独给语言代码块；禁止把多个步骤挤进同一代码块，每步代码块后必写要点和解释；禁止暴露作者本地或远端私有路径（一律用通用占位路径并提醒读者修改）。
