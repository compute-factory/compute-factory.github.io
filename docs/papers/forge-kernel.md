# ForgeKernel：架构解耦与自进化内核生成系统

这份报告精读清华大学与面壁智能等团队的论文《ForgeKernel: Self-Evolving Kernels Catching and Surpassing Experts and Agents》，依据为 `arXiv:2611.04998v1`（2026 年 11 月 3 日版本）。面对「当大模型已经能写出超越人类专家的单算子内核时，下一代内核智能体应当如何突破单次局部寻优」这一命题，论文把核心从单轮提示词微调转向**架构重规划**与**跨运行知识积累**：将架构规划与代码实现拆分为两个隔离角色，把验收通过的内核封存为下一轮新参考，并以独立硬件探针认证跨算子知识库。报告聚焦论文的核心思路、系统架构与实验影响，不涉及底层算子数学推导与源码细节。

## 主要工作

**ForgeKernel 打破了现有内核智能体「结构早早定型」与「经验随会话清零」两道瓶颈，在 NVIDIA 与华为昇腾芯片上追平顶尖专家库，并大幅领先已有内核生成系统。**

1. **双智能体职责解耦**：将负责工作划分与数据流决策的**架构智能体**（Architecture Agent）同负责编码与调试的**编码智能体**（Coding Agent）彻底分离，避免编译与局部修改绑架全局结构选择（[论文，§3.1–3.2、图 2](https://arxiv.org/pdf/2611.04998v1#page=4)）。
2. **跨轮封存参考自进化**：每一代通过验证的胜出内核都会被**封存为下一轮的不可见源码参考**，迫使系统从硬件实测行为出发重新审视并行结构，直至单轮提升落入测量噪声范围（[论文，§1、§3.4](https://arxiv.org/pdf/2611.04998v1#page=5)）。
3. **跨平台领先与榜单登顶**：<mark>在 NVIDIA H100 与 B200 的 27 个算子、29 个配置上，ForgeKernel 在 25 个配置持平或超越参考（几何平均 1.10×），在 Ascend 910C 8 个 level-4 算子上相对公开最佳领先 +25.1%，并在全部 4 个目标公开榜单排名第 1</mark>（[论文，摘要、§4.2、表 1](https://arxiv.org/pdf/2611.04998v1#page=1)）。

## 研究背景与核心约束

当基础模型已经能在不少算子上写赢人类专家时，制约已有内核智能体在复杂算子上继续突破的两道结构瓶颈是什么？

### 结构过早锁定问题

**已有内核智能体在性能落后于专家实现时，瓶颈通常不在局部指令微调不足，而在于早期选定的并行骨架把后续优化锁死在局部空间内。**

GPU 算子的性能上限由计算跨线程块划分、片上存储布局以及计算与数据搬运的重叠排程共同决定（[论文，§2.1](https://arxiv.org/pdf/2611.04998v1#page=3)）。在传统单智能体「生成—编译—测速—改写」循环中，编译报错、调试补丁与局部参数修改很快会占满上下文，使模型一旦产出一版正确代码，后续迭代就只在该既定结构内部修补，极少推翻重选工作划分或数据流（[论文，§1、§3.1](https://arxiv.org/pdf/2611.04998v1#page=3)）。

### 跨运行经验丢失问题

**传统单次优化任务结束时只留下一个最优内核文件，优化过程中探明的硬件机制随会话关闭而清零，导致每次运行都要重新试错。**

在单次目标驱动的搜索中，每次运行都从相同的初始认知出发；换一组输入形状或面对新算子时，上一轮积累的硬件规律无法迁移复用，每一代都在重复支付试错代价（[论文，§1、图 1](https://arxiv.org/pdf/2611.04998v1#page=2)）。同时，如果直接把专家库源码交给智能体去改写，虽然省去从零摸索，却相当于把优化空间直接锚定在原有代码的架构上限之上（[论文，§1、§5](https://arxiv.org/pdf/2611.04998v1#page=11)）。

## 系统架构与核心机制

既然单智能体把规划与调参混在一起容易卡死，ForgeKernel 如何拆解规划与实现、并在不泄漏源码的前提下沉淀可复用知识？

### 总体设计思路

**ForgeKernel 把优化过程拆成「外环定架构、内环写实现」的双智能体闭环，并借助封存参考与硬件知识库打通跨运行积累。**

![ForgeKernel 核心工作流：双智能体解耦、探针知识沉淀与跨轮自进化](/images/papers/forge-kernel/forgekernel-workflow-architecture.svg)

*图 1：ForgeKernel 核心工作流。参考实现经封存隔离后，由外环架构智能体制定并修订里程碑计划，内环编码智能体在源码隔离环境下逐条实现并接受同作业配对测速门禁；胜出内核可晋升为下一代参考，经探针实测的硬件机制则沉淀进共享知识库（综合自[论文，§3、图 1–2](https://arxiv.org/pdf/2611.04998v1#page=4)）。*

如图 1 所示，ForgeKernel 的设计围绕三项原则组织（[论文，§3.1、图 2](https://arxiv.org/pdf/2611.04998v1#page=4)）：第一，**原理与实现分离**，架构智能体只输出决策契约而非代码体，编码智能体在隔离源码的环境下专心落地；第二，**先立骨架、再调细节**，初始阶段优先锁定分块与异步排程，后续再逐项调优；第三，**测量驱动闭环**，所有修订、晋升与知识入库均以目标硬件真实测量而非主观猜测为准。

### 核心机制

上述思路落地为四项相互衔接的核心机制，分别解决防抄袭隔离、结构回溯、跨代接力与跨算子知识复用问题。

#### 封存参考隔离

**ForgeKernel 默认向系统提供「可测不可读」的封存参考，既能锚定硬件表现与性能目标，又杜绝编码端照搬源码或继承旧架构上限。**

论文将参考实现封存为可执行、可计时、可剖析但源文本不可见的对象（[论文，§3.1、§4.1](https://arxiv.org/pdf/2611.04998v1#page=6)）。架构智能体结合算子定义与封存参考的硬件测量行为制定优化目标，而编码智能体全程无法读取参考源码，执行框架也会直接拦截试图调用或将计算委托给参考实现的候选内核（[论文，§3.1、§4.1](https://arxiv.org/pdf/2611.04998v1#page=4)）。

::: details 点击展开：封存参考的观测通道与防源码泄漏边界
封存参考在屏蔽源码的同时，保留了三类用于架构诊断与验收的硬件观测通道（[论文，§3.1、§4.1、§4.4](https://arxiv.org/pdf/2611.04998v1#page=6)）：

1. **同作业冷 L2 配对计时**：在冷 L2 缓存条件下对参考与候选内核进行同作业重复计时，消除跨节点或 GPU 降频漂移，确立精确加速比。
2. **Nsight Compute（NCU）硬件计数器**：采集计算单元利用率、内存吞吐与停顿原因，辅助定位硬件瓶颈。
3. **流式汇编（Streaming/Shader Assembly, SASS）反汇编**[^sass-note]：核对编译后实际的寄存器分配与异步指令重叠情况，确保预期调度在硬件层真实生效。

[^sass-note]: 补充技术背景：PTX 是 NVIDIA 的虚拟指令集，而 **SASS** 是经编译器汇编后在具体 GPU 世代上真实执行的原生机器指令（[NVIDIA CUDA 二进制工具文档](https://docs.nvidia.com/cuda/cuda-binary-utilities/)）。查看 SASS 能直接核实异步数据搬运与矩阵乘指令在硬件层面是否并发。
:::

#### 里程碑契约与运行内修订

**架构智能体以有序里程碑 $M_0, M_1, \dots, M_k$ 约束编码顺序，并在内环停滞时依据测量轨迹回溯修改早期架构决策。**

架构智能体将并行分解、数据流向、分块大小、线程束分工与存储预算等全局决策排入初始里程碑 $M_0$，且 **$M_0$ 只要求结构完整与正确性通过而不设绝对速度门槛**，后续 $M_1$ 至 $M_k$ 再在既定骨架内逐项调优；里程碑只写设计要求、依赖关系与机制验证条件，不含算子实现代码（[论文，§3.2](https://arxiv.org/pdf/2611.04998v1#page=4)）。

编码智能体按依赖逐条实现并在同一 GPU 作业中验证正确性、相对速度与机制特征（[论文，§3.3](https://arxiv.org/pdf/2611.04998v1#page=5)）。当优化停滞、决策耗尽或无法通过门禁时，轨迹与测量证据回流给架构智能体重新评估：局部问题从对应任务恢复，涉及计算组织或数据流的结构调整则回退至最早受影响决策甚至重开 $M_0$；若修订后无法归因出性能增益，变更会被自动撤销并记录失败条件（[论文，§3.4](https://arxiv.org/pdf/2611.04998v1#page=5)）。

#### 跨轮参考晋升

**将上一轮通过验收的最优内核直接封存为下一轮参考，使系统无需人类重写基线即可持续推翻旧结构并向上攀升。**

一轮优化完成后，胜出的内核无需等待外部新基线，即可作为新一轮的封存参考（默认仍对新一轮智能体隐藏源码，典型目标设为相对上一代再提速 +5%）（[论文，§3.4、§4.1](https://arxiv.org/pdf/2611.04998v1#page=6)）。架构智能体重新测绘该内核的硬件行为并制定全新里程碑，直到后续轮次的性能增益确认不超过测量噪声阈值或预算耗尽为止（[论文，§3.4、图 1](https://arxiv.org/pdf/2611.04998v1#page=5)）。

#### 探针认证知识库

**硬件知识库仅收录经过目标 GPU 独立探针实测验证、且剥离了具体算子算法的底层硬件机制，保障经验可安全跨算子迁移。**

优化过程中发现的硬件机制按目标架构组织入库，每条知识记录机制本身、适用条件、触发症状、最小可运行示例及已知限制（[论文，§3.5](https://arxiv.org/pdf/2611.04998v1#page=5)）。候选条目必须先在目标硬件上通过独立微探针实验并附上测量证据，方能准入；后续任务引用条目时，仍须通过当前算子的里程碑门禁检验其实际效果（[论文，§3.5](https://arxiv.org/pdf/2611.04998v1#page=5)）。

::: details 点击展开：硬件知识库与单算子里程碑的经验隔离
为防止单个算子的特定写法污染其他算子，系统严格隔离两类经验载体（[论文，§3.2、§3.5](https://arxiv.org/pdf/2611.04998v1#page=5)）：

1. **里程碑属于单个算子**：承载具体算子的数学契约、分块逻辑与任务划分，不进入跨算子共享库。
2. **知识库只属于目标硬件**：仅记录算子无关的硬件能力用法（如异步拷贝或共享内存调度技巧的触发条件与注意事项）及最小可运行示例，从而可以跨算子与跨形状安全复用。
:::

## 实验与证据

这套双环架构与自进化机制在实际 GPU 集群、华为昇腾平台与公开权威榜单上带来了多大提升？各个组件是否真的不可替代？

### 公开榜单与跨平台性能

**ForgeKernel 在全部 4 个目标公开榜单排名第一，对已有内核生成系统取得 +39.4% 几何平均领先，并在绝大多数配置上追平或小幅超越顶尖人类专家库。**

分析实验结果时须先区分论文的两套运行目标（[论文，§4.1、§4.3](https://arxiv.org/pdf/2611.04998v1#page=6)）：§4.2 对比成熟专家库的实验以**追平参考**（parity, 1.0×）为目标，因此平均增益相对温和；而 §4.3 自进化实验则在追平基础上继续以**每轮 +5%** 向上冲刺。

### 跨轮自进化与架构演进

**自进化并不是在既有代码上反复微调超参，而是借助参考晋升重新诊断架构瓶颈，把非持久化执行改造成持久化重叠调度。**

|---|---|---|---|---|---|
| **无参考生成起步**：GDN prefill fwd | +82.6% | +9.5% | — | 约 **+100%** | [论文，表 2](https://arxiv.org/pdf/2611.04998v1#page=9) |
| **无参考生成起步**：GQA fwd (16:1) | +22.8% | +5.0% | — | 约 **+29%** | [论文，表 2](https://arxiv.org/pdf/2611.04998v1#page=9) |

图 5 与 GQA 案例共同说明了双层架构在破除局部最优中的作用（[论文，§4.5](https://arxiv.org/pdf/2611.04998v1#page=9)）：在 GQA fwd 的第一轮自进化中，架构智能体将「单块一退出」重构为「持久化执行」并分两步下发依赖计划——先改跨块状态管理仅提升 +0.8%，随后接入 Q 双缓冲预取再跳升 +6.1%，整轮合计 +9.9%。只有先改对结构骨架，后续流水预取的收益才能释放出来。

### 组件消融与边界

**消融实验与溯源统计验证了计划修订与知识库的作用，但也表明不同算子对反汇编与知识条目的敏感度差异显著。**

![原文图 6：SM90 队列外部知识采用分布与跨算子双向复用示例](/images/papers/forge-kernel/fig6-kb-adoption-and-reuse.png)

*图 6：(a) SM90 溯源队列中多数配置采用 6–10 条外部知识（43.5%）；(b) DSA sparse attn fwd 与 GQA bwd、FP16 GEMM 与 MHA bwd 之间形成双向跨算子知识回流。截取自[论文，§4.4、原文图 6](https://arxiv.org/pdf/2611.04998v1#page=10)。*

综合表 3 消融与图 6 溯源统计，可以得出三项经证据支持的结论与边界（[论文，§4.4、表 3、附录 E](https://arxiv.org/pdf/2611.04998v1#page=9)）：

1. **运行内修订不可缺少**：去掉计划修订（仅保留初始里程碑）后，3 项消融任务全线劣于完整系统（几何平均从 +0.4% 降至 −2.3%）。
2. **知识库在部分任务带来大幅拉升，且未被证明有负作用**：去掉知识库使 GDN prefill fwd 从 −1.5% 跌至 −16.4%，而 Attn bwd（+0.6% 对 +0.3%）基本中性；表 3 中无知识库下 DSA 的 +6.2% 采用不同输入单独报告，不可与完整系统的 +2.0% 作同条件对比。
3. **跨算子知识双向回流普遍发生，但非因果归因**：SM90 队列 23 个配置中最高复用 26–30 条知识，也有 17.4% 落在 0–5 条且保留零采用配置；图 6(b) 的双向互哺按引用与交付统计，附录 E 明确声明不构成因果性能归因（[论文，附录 E](https://arxiv.org/pdf/2611.04998v1#page=13)）。

## 局限性

1. **架构探索受限于智能体自身候选生成能力**：即便引入了反馈修订与跨代重规划，搜索空间依然受制于智能体能否提出有效架构方案，优化仍会停留在局部最优（[论文，§6](https://arxiv.org/pdf/2611.04998v1#page=11)）。
2. **知识库高度依赖特定硬件架构**：知识库中的硬件机制与适用条件强绑定具体 GPU 世代，跨硬件平台复用仍需重新适配与独立探针验证（[论文，§6](https://arxiv.org/pdf/2611.04998v1#page=11)）。
3. **任务覆盖与模型依赖尚存外推空白**：主实验聚焦单卡单算子优化，未覆盖多卡集合通信算子或整图编译；实验固定使用 Claude Fable 5.1 与 Claude Opus 5（融合稀疏注意力案例用 Claude Opus 5.5），论文未开展跨底座模型的迁移对照实验（[论文，§4.1、§4.3](https://arxiv.org/pdf/2611.04998v1#page=6)）。

## 结论

ForgeKernel 的核心贡献在于把自动内核生成从「单智能体在一版早期代码上打补丁」重塑为**架构规划与编码实现解耦、跨轮封存参考接力、探针认证知识跨算子复用**的系统闭环（[论文，§3、§7](https://arxiv.org/pdf/2611.04998v1#page=11)）。在工程应用上，面对已有成熟专家库的算子它能够稳定追平并小幅领先；而在稀疏注意力、线性注意力与复杂融合算子等缺乏现成专家实现的新计算模式上，跨代架构重构与知识迁移带来了最显著的加速复利（[论文，§1、§4.2–4.3](https://arxiv.org/pdf/2611.04998v1#page=2)）。
