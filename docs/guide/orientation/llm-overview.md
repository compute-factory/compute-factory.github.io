# 大模型概览

在进入人工智能基础设施（AI Infrastructure，简称 AI Infra，即支撑人工智能模型训练、微调与推理部署的软硬件底层系统）的具体技术细节之前，我们需要先弄清楚被这套系统所承载的核心对象——**大语言模型**。

一个模型在底层硬件上究竟是怎样表示文本的？它生成回答的过程在数学和计算上意味着什么？“训练”和“推理”为什么需要截然不同的硬件配置与系统设计？搞清楚这些基本问题，后续我们讨论显存占用、带宽瓶颈、算子优化和分布式并行时，所有的数字和工程折中才会有坚实的落脚点。

---

## 大语言模型的定义与能力边界

### 什么是大语言模型

**大语言模型**（Large Language Model，简称 LLM）是一类基于深度学习神经网络、拥有数十亿（$10^9$，通常写作 B，即 Billion）至数万亿（$10^{12}$，通常写作 T，即 Trillion）个**参数**（Parameter）的统计语言模型。

在这里，我们先明确两个高频基础概念：
- **参数（Parameter）**：神经网络中通过训练学习得到的浮点数权重（Weight）和偏置（Bias）。你可以把整个模型看作一个极其复杂的数学函数，而参数就是这个函数内部固定下来的系数。一个“7B 模型”，指的就是这个数学函数内部包含约 70 亿个浮点数参数。
- **自回归生成（Autoregressive Generation）**：当前主流大语言模型采用的工作方式。它的核心逻辑非常纯粹：给定一段已经出现的文本序列，模型计算出下一个最可能出现的词元（Token）的概率分布，从中选出一个词元拼接到原序列末尾；接着，把拼好后的新序列再次作为输入，预测再下一个词元，如此循环往复，直到生成结束标记或达到预设的长度上限。

![大语言模型自回归生成循环](/images/orientation/llm-overview/autoregressive-loop.svg)

如上图所示，模型在执行一次前向计算（步骤 2）后，并不会一次性吐出一整段话，而是输出整个词表上所有候选词元的概率分布（步骤 3）。系统从中采样选出单个词元 `x₅`（步骤 4）后，必须沿着底部的橙色虚线将其追加回输入序列末尾，开启下一轮循环。

> **注：条件概率视角下的语言模型**
> 从数学定义上看，假设一段文本被切分为词元序列 $x_1, x_2, \dots, x_t$，自回归大语言模型所做的事情，就是根据前 $t-1$ 个词元，计算第 $t$ 个词元取词表中任意候选值的条件概率分布：
> $$P(x_t \mid x_1, x_2, \dots, x_{t-1})$$
> 模型在每一轮前向计算中永远只往前预测一步。我们在网页或终端里看到的“流式打字机效果”，正是模型在底层硬件上一步接一步循环执行上述条件概率计算并采样输出的过程。

### 大语言模型的能力边界

由于大语言模型在海量人类文本上完成了条件概率建模，它压缩并内化了庞大的语言规律、事实常识与代码逻辑。这使得它能够直接完成开放域问答、文本摘要、多语言翻译、代码编写与多步逻辑拆解等任务。

但在工程落地与系统设计中，我们同样必须清楚它的固有能力边界：

1. **幻觉现象（Hallucination）**
   模型生成的本质是选择条件概率较高的后续词元，而非在结构化数据库中执行精确检索。当训练语料缺乏相关事实，或提示词引导到了模型知识的盲区时，模型仍会按照语法通顺、语义连贯的规律拼凑出看似合理但违背事实的内容，这种现象称为**幻觉**。
2. **知识截止（Knowledge Cutoff）与静态权重**
   模型训练完成并导出权重文件后，其内部参数便固定不变。模型无法依靠自身权重获知训练语料截止日期之后的实时信息，也无法在不借助外部存储的情况下持久记住某次单轮对话之外的新增私域事实。
3. **上下文窗口（Context Window）的长度限制**
   **上下文窗口**是指模型在单次生成过程中，能够同时接收并处理的输入词元与已生成词元的最大总数。受限于模型内部位置编码机制的有效范围，以及计算耗时、显存占用随序列长度增长而急剧上升的物理约束，任何模型都存在明确的上下文长度上限（例如 8K、32K 或 128K Token）。
4. **缺乏原生精确计算与确定性逻辑校验**
   对于多位数算术运算、复杂符号推导或严格受控的业务规则校验，仅靠神经网络的前向概率预测难以保证 100% 的确定性，工程上通常需要结合外部代码解释器或函数调用（Tool Calling）来补足。

## Token 与 Tokenizer：文本切分与多语言编码差异

### 什么是 Token 与 Tokenizer

神经网络本质上是一系列矩阵乘法与非线性函数运算的组合，它无法直接读取“你好”或“Hello”这样的字符，只能处理数字。因此，任何文本在送入模型之前，都必须经过一道标准化转换工序：

- **Token（词元）**：大语言模型处理文本的最小基本单位。一个 Token 可以是一个完整的英文单词、一个词根或词缀、一个中文字符，甚至只是复杂生僻字在字节编码下的一个片段。
- **Tokenizer（分词器）**：负责在“原始字符串”与“整数编号序列（Token IDs）”之间进行双向转换的独立组件。
  - **编码（Encode）**：将用户输入的字符串按照既定规则切分为多个 Token，并查表映射为对应的整数编号（Token ID）。
  - **解码（Decode）**：模型推理输出一串整数编号后，Tokenizer 查表将它们还原并拼接为人类可读的字符串。
- **词表（Vocabulary）**：Tokenizer 内部维护的一张完备映射字典，记录了每一个 Token 字符串与唯一整数 ID（从 $0$ 到 $V-1$，$V$ 为词表大小）的对应关系。主流开源模型的词表大小通常在 $32,000$ 到 $150,000$ 之间。

![Tokenizer 编解码链路与 BPE 合并机制](/images/orientation/llm-overview/tokenizer-bpe.svg)

> **注：为什么不直接按“单个字符”或“完整单词”切分？**
> - 如果按**完整单词**切分：人类语言中的词形变化（如 `run`、`runs`、`running`）、专有名词和复合词无穷无尽，会导致词表体积膨胀到数百万级；且一旦遇到词表外的新词（Out-Of-Vocabulary，简称 OOV），模型就会完全失效。
> - 如果按**单个字符或字节**切分：词表虽然极小，但一段普通文本会被拆成极其冗长的序列。序列变长会直接导致模型单次计算量呈平方级或线性成倍增加，同时稀释每个位置所承载的语义密度。
>
> 为了在“词表大小”和“序列长度”之间取得平衡，现代大语言模型普遍采用**子词切分（Subword Tokenization）**算法，其中最核心的代表是 **BPE**。

### BPE（字节对编码）的工作原理

**BPE**（Byte-Pair Encoding，字节对编码，主流模型广泛使用的是直接在 UTF-8 字节流上操作的 Byte-level BPE）是一种自底向上的子词构建算法。对照上方示意图的 **B 区**，它的训练（构建词表）过程分为三步：

1. **初始状态**：将基础词表设为所有单个字节（共 256 个基础字节），任何 UTF-8 文本都可以无损拆解为字节序列，从而从根源上消除了未知字符（OOV）问题。
2. **高频合并**：扫描大规模训练语料，统计当前所有相邻配对的 Token 组合中，出现频率最高的一对（例如字母 `'i'` 和 `'n'` 经常相邻出现，就将它们合并为一个新的 Token `'in'`），并将其加入词表。
3. **迭代至目标容量**：不断重复“统计最高频相邻对 $\rightarrow$ 合并为新 Token”的过程，直到词表中的 Token 总数达到预设的词表大小 $V$。

通过这种机制，高频词（如 `"learn"`、`"ing"`、`"算力"`）会被合并成单个完整的 Token；而罕见词或拼写错误则会退化拆解为多个较短的子词甚至单个字节。

### 多语言编码差异与系统性能影响

不同语言在同一个 Tokenizer 下的切分效率往往存在显著差异，这种差异由两方面共同决定：**底层字符编码的字节长度**与**训练语料中各语言的占比**。

1. **UTF-8 编码的字节基数差异**
   在 UTF-8 编码标准下，英文字符与常见半角符号仅占 **1 个字节**，而绝大多数常用汉字需要占用 **3 个字节**。如果一个模型的词表主要基于英文语料训练生成，词表中合并出的中文完整汉字和常用词组就会很少。当遇到未合并的汉字时，Byte-level BPE 会将其拆解为 3 个独立的字节级 Token（参见上方示意图的 **C 区**）。
2. **压缩率（字符/Token 比）的直观对比**
   我们可以用下面的 Python 代码直观对比不同模型分词器对同一语义的中英文切分结果：

```python
# 示例：对比同一语义在中英文下的 Token 切分粒度
en_text = "Large language models run on GPUs."
zh_text = "大语言模型运行在图形处理器上。"

# 在常见多语言 Tokenizer（如 Qwen / Llama 3 词表）下的典型切分示意：
# en_text -> ['Large', ' language', ' models', ' run', ' on', ' GPUs', '.']  (共 7 个 Token)
# zh_text -> ['大', '语言', '模型', '运行', '在', '图形', '处理器', '上', '。'] (共 9 个 Token)

# 而在早期以英文为主、词表较小的 Tokenizer（如初代 Llama 32K 词表）下：
# 部分汉字未能作为整体收录进词表，会被拆成 2~3 个字节片段，导致同一句中文消耗 20 个以上的 Token。
```

3. **对 AI Infra 系统的直接影响**
   在 AI Infra 工程师眼中，**模型的计算开销、显存占用和生成耗时，永远是以 Token 数量而非人类可读的字数来结算的**。

![不同 Tokenizer 对 500 字中文文本的切分数量与系统开销对比](/images/orientation/llm-overview/token-efficiency-chart.svg)

如上方实测数据对比图所示，自回归模型每生成一个 Token，都需要将数十亿个模型参数从显存搬运到计算核心执行一次完整的前向运算。同样输出一段 500 字的中文技术回答，多语言大词表（如 Qwen2.5 / DeepSeek）仅需约 **290 个 Token**，而早期 32K 英文主导词表（如初代 Llama）则需要 **740 个 Token**。这意味着在相同硬件上，后者的**总生成耗时**和**推理中间状态缓存（KV Cache）占用的显存空间**都会直接膨胀至前者的 **$2.55$ 倍**，且相同上下文窗口上限所能容纳的中文实际字数也会缩水六成以上。

## 预训练、微调与推理的边界

大语言模型从原始语料到最终面向用户提供问答服务，整个生命周期清晰地划分为三个阶段：**预训练**、**微调**与**推理**。区分这三件事的边界，是理解训练系统与推理系统架构差异的前提。

![预训练、微调与推理阶段的计算链路及显存构成对比](/images/orientation/llm-overview/training-vs-inference.svg)

### 1. 预训练（Pre-training）：从零学习通用规律

**预训练**是指从一个参数完全随机初始化的空白神经网络开始，在数万亿至数十万亿 Token 的海量无标注文本（网页、书籍、代码仓库、学术论文等）上进行自监督学习的过程。

- **计算过程**：如上图上半部分所示，在每一轮迭代（Step）中，系统需要走完一个完整的闭环：
  1. **前向传播**（Forward Pass，将输入数据依次通过模型各层计算出预测分布，同时在显存中暂存各层的中间**激活值** Activations）；
  2. 计算预测结果与真实下一个 Token 之间的**损失函数**（Loss Function，衡量模型预测分布与真实标签差距的数学指标）；
  3. **反向传播**（Backward Pass，利用微积分链式法则，从最后一层往前逐层计算损失函数对每个参数的**梯度** Gradient $\nabla W$，即参数应当朝哪个方向调整、调整多少的导数信号）；
  4. **优化器更新**（Optimizer Step，如 AdamW 优化器，结合当前梯度与历史动量状态，计算更新量并修改模型权重 $W \leftarrow W - \eta \cdot \Delta W$）。
- **阶段产出**：得到具备广泛语言理解与知识储备的**基座模型**（Base Model）。基座模型只懂得“顺着上文往下续写”，当你输入“请问什么是 GPU？”，它可能会续写出“请问什么是 CPU？请问什么是内存？”（因为它见过很多试题列表），而不会直接回答你的问题。
- **Infra 特征**：计算量极大，通常需要数千张高性能 GPU 组成集群连续满负荷运转数周至数月，对跨机高速网络通信、容错恢复与分布式并行策略要求极高。

### 2. 微调（Fine-tuning / Post-training）：对齐指令与偏好

为了让基座模型学会听懂人类指令、按照助手的方式回答问题，或在特定垂直领域（如医疗、法律、代码辅助）表现更优，需要在预训练之后进行**微调**（现代流程中常统称为后训练 Post-training）。

- **有监督微调（Supervised Fine-Tuning，简称 SFT）**：使用数万至数百万条高质量的“指令-标准回答”配对数据，继续执行与预训练相同的“前向传播 $\rightarrow$ 计算损失 $\rightarrow$ 反向传播求梯度 $\rightarrow$ 优化器更新权重”闭环，使模型掌握对话格式与指令遵循能力。
- **偏好对齐（Alignment）**：通过人类反馈强化学习（RLHF）或直接偏好优化（DPO）等算法，让模型学会在多个候选回答中倾向于更准确、更有帮助且安全的表述。
- **参数更新范围**：微调既可以更新全部模型参数（全量微调 Full Fine-Tuning），也可以冻结原始权重、仅训练额外挂载的少量低秩矩阵参数（参数高效微调 PEFT，如 LoRA）。
- **Infra 特征**：数据量远小于预训练，通常使用数张到数十张 GPU 在数小时至数天内完成。但由于同样包含反向传播和优化器更新，单卡显存不仅要存模型权重，还要存梯度、优化器状态和前向激活值。

### 3. 推理（Inference）：冻结权重，服务请求

**推理**是指模型训练和微调全部结束后，将所有模型参数**彻底冻结（只读，不再修改）**，部署到服务器上接收实际用户的输入并生成回复的过程。

- **计算过程**：对照上图下半部分，推理阶段**只有前向传播（Forward Pass）**。系统不需要计算损失函数，不需要执行反向传播求梯度，也不需要运行优化器更新权重。
- **Infra 特征**：由于彻底省去了梯度、占大头的优化器状态以及为反向传播保留的中间激活值，单次推理所需的显存远小于训练（主要由只读权重和随序列增长的 KV Cache 构成）；但推理直接面向在线用户或业务调用，系统设计的核心指标从训练时的“集群总吞吐量”转变为“首字响应延迟（TTFT）”、“单字生成速度（TPOT）”与“单位算力成本下的并发服务能力”。

### 三阶段核心边界对照表

为了方便在后续章节中随时核对，我们将这三个阶段的关键差异汇总如下：

| 对比维度 | 预训练（Pre-training） | 微调（Fine-tuning） | 推理（Inference） |
| :--- | :--- | :--- | :--- |
| **起点模型** | 随机初始化的空白网络 | 预训练完成的基座模型 | 训练/微调完成的成品模型 |
| **数据规模** | 数万亿（Trillions）Token 无标注语料 | 数千至数百万条高质量指令/偏好数据 | 在线实时到达的单条或成批用户请求 |
| **执行计算** | 前向传播 + 反向传播 + 优化器更新 | 前向传播 + 反向传播 + 优化器更新 | **仅前向传播** |
| **参数状态** | 全量参数持续更新 | 全量或局部参数持续更新 | **所有参数只读冻结** |
| **显存主要占用** | 权重 + 梯度 + 优化器状态 + 激活值 | 权重 + 梯度 + 优化器状态 + 激活值 | **权重 + KV Cache + 少量临时激活值** |
| **硬件与时间规模** | 数百至数万卡，持续数周至数月 | 单卡至数十卡，持续数小时至数天 | 单卡至多卡常驻服务，单请求毫秒至秒级 |

## 文本模型与多模态模型的差异

随着应用场景的扩展，大模型早已不再局限于处理纯文本。理解纯文本模型与**多模态模型**（Multimodal Model，能够同时接收或处理文本、图像、音频、视频等多种信息形态的模型）在结构上的异同，能帮助我们看清推理框架是如何用同一套底层机制支撑不同形态模型的。

### 纯文本大语言模型的输入流水线

在纯文本大模型中，输入处理链路是单一且齐整的：
1. 输入字符串经过 **Tokenizer** 切分，变成一维整数数组（Token IDs）；
2. 整数数组通过模型的**词嵌入层**（Embedding Layer，一张维度为 $[\text{词表大小 } V, \text{隐藏层维度 } d]$ 的查找表），将每个整数 ID 映射为一个长度为 $d$ 的连续浮点数向量；
3. 这串特征向量序列直接送入后续的 **Transformer 主干网络**（Backbone，模型中负责主体特征交互与自回归预测的核心堆叠层）进行计算。

### 多模态模型是怎么工作的

以工业界最常见的**视觉-语言模型**（Vision-Language Model，简称 VLM，支持同时输入图片和文字并进行问答的模型）为例，它在保持大语言模型自回归生成主干不变的前提下，在输入端增加了一条跨模态转换支路：

![多模态视觉-语言模型双支路输入与统一序列拼接架构](/images/orientation/llm-overview/text-vs-multimodal.svg)

对照上方架构图，多模态输入在前向计算中的流转分为三个关键步骤：

1. **模态编码器（Modality Encoder）**
   图像或音频无法像文字一样通过静态词表查表。多模态模型会前置一个专门的编码网络——例如处理图像时使用**视觉编码器**（Vision Encoder，通常是基于 Vision Transformer，即 ViT 架构的神经网络）。视觉编码器先将输入图片切分为一个个固定大小的像素网格块（Image Patch，例如 $14 \times 14$ 像素为一个小块），再经过若干层计算，将每一个像素块提取为一个维度为 $d_v$ 的高维特征向量。
2. **模态投影层 / 适配器（Projector / Adapter）**
   视觉编码器输出的特征向量维度 $d_v$，通常与大语言模型主干网络的隐藏层维度 $d$ 不一致，且两者的特征空间分布不同。因此需要经过一个轻量级的**投影层**（Projector，通常由一两层线性全连接网络或交叉注意力层构成），把视觉特征向量映射并对齐到大语言模型的向量空间中，变成一个个维度为 $d$ 的**视觉词元向量（Visual Tokens）**。
3. **统一序列拼接与自回归生成**
   对齐后的视觉词元向量 `[N_img, d]`，与文本通过 Embedding 查表得到的文本词元向量 `[N_txt, d]`，具有完全相同的向量维度 $d$。系统将它们按照输入位置顺序直接拼接成一条统一的向量序列（如右半图所示：`[Img₁, Img₂, ..., Imgₙ, 文本向量₁, 文本向量₂, ...]`），一并送入 Transformer 语言模型主干，后续的自回归生成过程与纯文本模型完全一致。

### 结构与系统负载上的核心差异

从 AI Infra 的视角来看，多模态模型与纯文本模型相比，会给底层推理和训练系统带来三个显著的变化：

1. **输入序列长度急剧膨胀（Token 数量激增）**
   一句简短的提问“图里有什么？”在文本侧只有不到 10 个 Token；但一张高分辨率图片经过切片编码后，往往会转化为数百甚至数千个 Visual Token（对于一段几十秒的视频，更可能高达上万个 Token）。这会导致推理请求在读取输入的初始计算阶段（Prefill 阶段）耗时大幅上升，并迅速占满显存缓存。
2. **异构网络结构的计算与并行不对称**
   纯文本模型从头到尾都是结构完全一致的层堆叠，在做多卡分布式切分时非常规整。而多模态模型包含了“视觉编码器 + 投影层 + 语言模型主干”三个规模差异巨大的模块（例如 4 亿参数的 ViT 搭配 700 亿参数的 LLM），不同模块对算力和显存的需求比例截然不同，给多卡负载均衡与流水线调度带来了额外挑战。
3. **数据预处理（Data Preprocessing）成为潜在瓶颈**
   纯文本分词仅需极少的 CPU 计算；而多模态请求在进入 GPU 之前，需要先完成图像解码、尺寸缩放（Resize）、像素归一化或视频抽帧。在高并发服务或大规模分布式训练中，如果 CPU 端的多媒体解码速度跟不上，就会出现 GPU 空闲等待 CPU 喂数据的现象。

## 小结

在这一章中，我们从系统视角梳理了大语言模型的基本面貌：
1. **大语言模型**是通过数十亿至数万亿浮点数参数构建的自回归条件概率模型，它以“逐词元预测下一步”的方式工作，受限于幻觉、静态权重和上下文窗口上限。
2. **Tokenizer** 通过子词切分（如 BPE）在人类文本与整数 Token ID 之间架起桥梁；模型的计算量与显存开销严格按 Token 数量结算，不同语言和词表设计会直接影响系统的实际运行成本。
3. **预训练与微调**需要完整执行前向传播、反向传播与优化器参数更新，显存与算力开销庞大；而**推理**冻结了全部参数，仅执行前向传播，优化重心转向低延迟与高并发。
4. **多模态模型**通过专用编码器与投影层，将图像、音频等信息转化为与文本同维度的向量序列送入语言主干网络，同时也带来了输入 Token 激增与异构计算的工程挑战。

明确了模型在做什么之后，下一节《AI Infra 概览》我们将顺着一条真实的推理请求往底层走，看看模型、推理引擎、CPU 内存与 GPU 显存是如何协同完成这次计算的。

   - Sennrich et al. (2016), [*Neural Machine Translation of Rare Words with Subword Units*](https://arxiv.org/abs/1508.07909)：将 BPE（字节对编码）引入自然语言处理子词切分的经典论文。
   - Hugging Face Documentation, [*Summary of the tokenizers*](https://huggingface.co/docs/transformers/tokenizer_summary)：详细介绍 BPE、Byte-level BPE、WordPiece 与 Unigram 等主流分词算法的实现细节。

3. **预训练、微调与后训练全流程**
   - Ouyang et al. (2022), [*Training language models to follow instructions with human feedback (InstructGPT)*](https://arxiv.org/abs/2203.02155)：清晰定义了“预训练基座 $\rightarrow$ 有监督微调（SFT） $\rightarrow$ 偏好对齐（RLHF）”的三阶段现代大模型训练范式。
   - Dubey et al. (2024), [*The Llama 3 Herd of Models*](https://arxiv.org/abs/2407.21783) / Qwen Team (2024), [*Qwen2.5 Technical Report*](https://arxiv.org/abs/2412.15115)：工业级开源大模型技术报告，涵盖多语言词表扩充、预训练数据配比、后训练及多模态扩展的完整工程实践。
4. **视觉-语言多模态模型（VLM）**
   - Dosovitskiy et al. (2020), [*An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale (ViT)*](https://arxiv.org/abs/2010.11929)：提出将图像切分为固定大小 Patch 并编码为特征向量序列的 Vision Transformer 架构。
   - Liu et al. (2023), [*Visual Instruction Tuning (LLaVA)*](https://arxiv.org/abs/2304.08485)：展示如何通过视觉编码器（ViT）与线性投影层（Projector）将图像特征接入大语言模型主干的典型多模态架构。
